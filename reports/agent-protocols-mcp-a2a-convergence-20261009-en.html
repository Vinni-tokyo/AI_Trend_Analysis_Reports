There Was No Protocol War
— How MCP and A2A Divided the Layers

MCP connects tools, A2A delegates between agents. What that division demands of organizations
Report date: October 9, 2026 | Standard report (5-8 pages) | Data collected: October 9, 2026

Top 5 Trends

The central claim of this report
MCP and A2A were never competitors. They took different layers. The practical answer in 2026 is a hybrid that uses both, and only after that choice is settled does the real homework appear. This report answers not "which one wins" but "what must be decided now."

1. Not a contest but a division of layers — both now sit under the same foundation

Situation: In 2025 this read like a standards contest. In 2026 the two protocols did not push each other out. MCP was donated to the Linux Foundation in December 2025, and A2A became a hosted project of the Agentic AI Foundation on August 17, 2026. Both now sit under the same foundation umbrella. Nobody won. The layers were simply divided.

MCP — connects a model to the outside world

• Layer it owns: the path by which a single agent reaches external data, APIs and file systems
• Mechanism: a JSON-RPC client–server interface for tool invocation and typed data exchange
• Origin: started by Anthropic, moved to an open standard
• Its question: "what can this agent reach?"

A2A — hands work between agents

• Layer it owns: agents from different vendors and frameworks discovering each other and delegating work
• Mechanism: JSON-RPC 2.0 over HTTPS, covering discovery, authentication and delegation
• Origin: developed by Google, donated to the Linux Foundation
• Its question: "who can this agent hand work to?"

🔗 Related Links: Model Context Protocol | A2A Protocol | Linux Foundation

Outlook: That both protocols ended up under one roof is itself the signal. The live question moves from "which do we pick" to "how do we fit the two layers together."

📊 Credibility Assessment: 9/10
Strengths: Linux Foundation announcements, the A2A first-anniversary release (April 9, 2026) and the Agentic AI Foundation transfer date (August 17, 2026) are all verifiable.
Weaknesses: "It was never a contest" is a reading made with hindsight; in 2025 the situation was genuinely reported as a standards race.

2. Adoption by the numbers — MCP at 400M monthly downloads, A2A at 150+ organizations

Situation: The two protocols spread in different shapes. MCP grew developer by developer; A2A gathered organization by organization. MCP's monthly SDK downloads went from roughly 2 million at its November 2024 launch to over 97 million by March 2026, and co-creator David Soria Parra noted 110 million monthly downloads at the 16-month mark — a milestone React took three years to reach. After a new stateless specification shipped on July 28, 2026, downloads passed 400 million a month, roughly four times this year's starting point.

MCP — the depth of the ecosystem

• Monthly SDK downloads: past 400 million as of October 2026
• Public servers: over 10,000 at the December 2025 Linux Foundation donation; an independent Q1 2026 census indexed 17,468
• Enterprise penetration: 28% of Fortune 500 companies have deployed MCP
• Shape of growth: individual developers wiring up their own tools, spreading from the bottom

A2A — who is at the table

• Supporting organizations: from roughly 50 in April 2025 to over 150 by April 2026
• Participants: AWS, Cisco, Google, IBM, Microsoft, Salesforce, SAP, ServiceNow
• Live sectors: supply chain, financial services, insurance, IT operations
• Production users: IBM, Cisco, SAP and ServiceNow are confirmed

The metrics differ because the targets differ. MCP is used the moment one person attaches a tool to their own agent. A2A requires two organizations to agree. Counting downloads for the first and participating organizations for the second is the natural fit.

🔗 Related Links: MCP documentation | A2A first-year announcement

Outlook: MCP's fourfold growth is tied to the July stateless specification. A lighter connection model means more places to attach. A2A's pace, by contrast, is bound to how fast organizations agree with each other.

📊 Credibility Assessment: 7/10
Strengths: The 150-organization figure comes from the Linux Foundation's official release. The 97M and 110M milestones are consistent across multiple sources.
Weaknesses: The "400 million" figure and public server counts (15,930–17,468) vary by who is counting and how. The trend is clear, but a single number should not be treated as definitive.

3. The 2026 answer is hybrid — what goes where

Situation: Practice has already settled the question. Most production agent stacks run MCP at the tool layer and A2A for inter-agent coordination. Each agent attaches its own tools via MCP, and A2A is layered on top only where those agents must hand work to one another.

Lower layer — inside each agent

• Databases, files, internal APIs → MCP
• Only the tools each agent actually needs
• Permissions should be scoped most tightly at this layer
• Easy to change: adding or removing a tool barely affects other agents

Upper layer — between agents

• Capability advertisement, discovery, task delegation → A2A
• Needed only where agents from different vendors must connect
• Authentication becomes the sticking point once organizational boundaries are crossed
• Hard to change: it depends on agreement with the other party

One year and nine months later, that race ended not in a winner but in a division of layers. Where that report covered the design inside MCP, this one covers the place MCP occupies from outside.

Outlook: Once hybrid becomes the default, the weight of the decision shifts from "what do we use" to "where do we draw the boundary." Which work finishes inside one agent, and where it passes to another, becomes the core of the design.

📊 Credibility Assessment: 8/10
Strengths: The statement that most production stacks run MCP for tools and A2A between agents appears consistently across multiple technical analyses.
Weaknesses: No public survey quantifying "most" was found. This is based on industry observation rather than measured data.

4. The other candidates — where ACP and ANP sit

Situation: These are not the only two protocols, though each aims at a slightly different spot. ACP (Agent Connect Protocol), led by IBM and the AGNTCY collective, takes a deliberately minimal approach that maps agent interactions directly onto HTTP verbs: POST to create a task, GET to check status, PUT to update, DELETE to cancel. Because the surface is specified in OpenAPI, any tool that speaks REST can interact with an ACP agent without a specialised SDK.

ACP — REST-friendly, central registry

• Mechanism: direct mapping to HTTP verbs, specified in OpenAPI
• Discovery: a centralized registry model where agents register capabilities with a directory service and clients query it
• Backing: the AGNTCY collective — Cisco, LangChain, LlamaIndex, Galileo, Dell, Oracle, Red Hat
• Governance: donated to the Linux Foundation in July 2025

Other currents

• ANP (Agent Network Protocol): aimed at agent communication over open networks
• Matrix-based approaches: adopted in systems such as Alibaba's HiClaw
• XMPP: reuses a long-established messaging standard, though it was not designed for agents
• None of the three has yet reached the adoption scale of MCP or A2A

🔗 Related Links: AGNTCY | Linux Foundation projects

Outlook: ACP's REST affinity makes it easy to layer onto existing systems, but its centralized registry differs philosophically from A2A's distributed discovery. For now the MCP + A2A pairing is the default, with ACP likely to remain an option for organizations with deep REST estates.

📊 Credibility Assessment: 8/10
Strengths: ACP's design (HTTP verb mapping, OpenAPI, central registry), the AGNTCY member list and the Linux Foundation donation date are all confirmed.
Weaknesses: ANP and Matrix-based approaches lack public adoption metrics, so only their positioning is described. No comparable figures could be provided.

5. What remains after the division — the gap in authorization and audit

Situation: Settling the protocols settles communication. What remains is "may this agent do that?" A2A specifies discovery, authentication and delegation, and has added authentication schemes reflecting the demands of regulated sectors. But a protocol does not decide who has been authorized for what on an organization's behalf. Whether permissions narrow when work is delegated, and whether an audit trail continues across the boundary, still depends on each organization's own design.

What the protocol answers

• How to find the other party (discovery)
• In what form to exchange messages (transport and serialisation)
• What capabilities to declare (capability advertisement)
• How to verify the other party is genuine (the framework for authentication)

What the organization must decide

• Permission propagation: do permissions narrow on delegation, or carry over intact?
• Audit continuity: who records actions once the boundary is crossed?
• Scope-drift detection: what alerts you when the granted scope is exceeded?
• Rollback: where does delegated work stop when it goes wrong?

Continue reading — This site's October 9, 2026 report, "The Bar a Shelved Model Left Behind", framed OpenAI's reason for not shipping its own model as "the ability to stay within authorization." The gap in this section is the same problem viewed at the protocol layer rather than the model layer. Whether one model respects its scope, and whether scope travels correctly between agents, are a matched pair of questions.

Outlook: With communication standards stable, the next standardisation pressure moves to authorization and audit: how permissions are narrowed on delegation, and what form an audit record takes once it crosses a boundary.

📊 Credibility Assessment: 7/10
Strengths: That A2A extended its authentication schemes in response to regulated-sector demand is confirmed. The separation between protocol and authorization design matches the technical documentation.
Weaknesses: The forecast that authorization and audit become the next standardisation target is this report's judgement. No public evidence of specific standardisation work in progress was confirmed.

Competitive Landscape

A four-layer structure at the protocol level

Building an agent system means deciding four layers. The lower ones are easy to change; the higher ones carry a heavy reversal cost. (This classification is our own analysis.)

Layer What is decided Typical choice Cost of reversal
Layer 1 — Tool connection How an agent reaches data, APIs and files MCP Low — tools can be added and removed individually
Layer 2 — Internal coordination Dividing work among agents inside one organization Framework-native features, or A2A Medium — absorbed through internal redesign
Layer 3 — Cross-organization delegation Handing work to agents from another vendor or company A2A (sometimes ACP) High — requires agreement with the other party
Layer 4 — Authorization and audit Who is authorized for what, and what gets recorded No standard — designed by each organization Very high — redesigning after an incident is too late

Application Ideas

Approaches observed in the market.

1. Map the layers you already run - Sort existing agents into tool connection, internal coordination and cross-organization delegation, and write down on one page what each currently uses

2. Draw boundaries before adopting A2A - Decide which work finishes inside a single agent first, deferring the decisions that are expensive to reverse

3. Test permission propagation - Check whether permissions narrow when one agent delegates to another, and whether the audit trail survives the boundary

Executive Summary

Key Findings

  • It was a division, not a contest: MCP moved to the Linux Foundation in December 2025 and A2A in August 2026, placing both under one umbrella.
  • Adoption scales differ: MCP passed 400 million monthly SDK downloads with 28% of the Fortune 500 deploying it; A2A passed 150 supporting organizations.
  • Practice has already decided: the default is a hybrid — MCP for tool connection, A2A for inter-agent delegation.
  • Reversal cost varies by layer: tool connections are easy to change, but cross-organization delegation depends on agreement with the other party.
  • The next gap is authorization and audit: protocols govern communication, but how permissions propagate on delegation and how audit continues is the organization's design task.

Guidance by situation

Just starting to build agents → start with MCP
Why: tool connection has the lowest reversal cost, and the ecosystem is deep enough that most things are already connectable.
Need to join agents across teams → start with boundary design
Why: before layering on A2A, decide how much finishes inside a single agent. Moving that boundary later is expensive.
Operating in a regulated sector → start with Layer 4
Why: this is the area protocols do not answer, and designing it after an incident is too late.

Overall sentiment: Positive. Standards converging into layers rather than fragmenting is good news for adopters. It is worth being explicit, however, that settling communication standards does not settle the authorization problem.

Key Terminology

MCP (Model Context Protocol) — A standard for connecting AI models to external data, APIs and file systems. Like a plug socket standard, it lets any tool attach in the same shape.
A2A (Agent2Agent) — A standard that lets agents built by different companies and frameworks find each other, verify identity, and hand over work.
ACP (Agent Connect Protocol) — A standard led by IBM and the AGNTCY collective that maps agent interactions directly onto HTTP verbs (POST, GET, PUT, DELETE).
JSON-RPC — A simple convention for one program to ask another to "run this function with these values." Both MCP and A2A use it.
Stateless design — An approach where the server keeps no memory of earlier exchanges and each request carries everything it needs. Connections become lighter and easier to scale.
Capability advertisement — An agent publicly declaring "here is what I can do." It is the basis on which another agent decides whether to delegate.
Agentic AI Foundation — A foundation created under the Linux Foundation specifically for agentic AI standards. Both MCP and A2A belong to it.
