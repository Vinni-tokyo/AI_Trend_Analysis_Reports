2. v1.0プラグインファースト設計とマーケットプレイス生態系

現状：Difyは2025年のv1.0リリースで「Beehive」モジュラーアーキテクチャを採用し、プラグインファースト（Plugin-First）設計に移行しました。各モジュールが独立して動作するため、開発者は全体システムに影響を与えることなく特定の部分だけを修正・拡張できます。Dify Marketplaceにはモデルプロバイダ、ツール、データソース、エージェント戦略、拡張機能などさまざまなプラグインが登録されています。

アーキテクチャの要点

• Beehive構造：モジュール式の独立稼働
• LLMオーケストレーション：数百のモデルを接続
• Visual Studio：ドラッグ&ドロップのワークフロー
• Deployment Hub：API/チャットボット/埋め込みのワンクリック配備
• Prompt IDE：モデル比較とプロンプト設計

マーケットプレイスの構成

• モデルプロバイダ：OpenAI、Anthropic、Llama、ChatGLMなど
• 組み込みツール：50種以上（Google検索、DALL·E、SD、WolframAlpha）
• エージェント戦略：Function Calling／ReAct
• Creator Center：ワークフローテンプレートの共有
• PartnerStack：アフィリエイト収益モデルの導入

📊 信頼性評価： 9/10

改善点：マーケットプレイス登録プラグインの正確な数は非公開

3. Agentic RAGと自律推論ノードの台頭

現状：従来の一発型RAG（検索→生成）と異なり、DifyのAgent Nodeは意図分析、ツール選択、クエリ書き換え、根拠評価、フォールバックなど反復的な推論を行います。これによりグラウンディングと信頼性は大幅に向上しますが、レイテンシとコストも増加します。Workflow内のAgent Nodeは固定フローから一部のステップを切り出し、LLMが自律的に判断する領域を設ける仕組みです。

Agentic RAGの特徴

• 反復的検索：一発型 → 多段階推論
• クエリ書き換え：LLMが検索語を自動最適化
• 根拠評価：検索結果の信頼度を自己判断
• フォールバック機構：失敗時に別ツールで再試行
• 複数KB統合：人事・技術・製品KBを同時に検索

クラシックRAG vs Agentic RAG

• 応答精度：Agenticが15-30%高い（推定）
• レイテンシ：1.5-3倍に増加
• API費用：平均2倍に増加
• 適合用途：複雑な多段階クエリ
• 不向き：単純なFAQ、短い問答

📊 信頼性評価： 7.5/10
強み：Dify公式ブログの技術文書に基づく正確な説明
改善点：15-30%の精度向上や2倍のコスト増は業界一般推定であり、出典の多様化が望ましい
🔗 関連リンク： Agentic RAGブログ | Agent Node紹介 | Agent Nodeドキュメント

展望：2026年後半にはマルチエージェント（Agent-to-Agent）連携ノードや、コスト最適化ルーティングが標準機能として定着する見込みです。

現状：Difyは参入障壁を最小化する多層価格モデルを採用し、個人開発者から大企業まで幅広く取り込んでいます。クラウドの無料プランSandbox（月200クレジット）、Professional（月59ドル）、Team（月159ドル）、Enterprise（カスタム）で構成され、セルフホストではCommunity（無料）、Premium（AWS AMI）、Enterprise（ライセンス）の選択肢があります。

📖 主要用語の説明

LLMOps：LLMアプリケーションの開発・配備・監視・改善を統合する運用方式（DevOpsのLLM版）。
BaaS（Backend-as-a-Service）：認証、データベース、ストレージなどバックエンド機能をマネージドで提供するサービス。
RAG（Retrieval-Augmented Generation）：外部知識を検索してLLM応答に根拠を与える手法。
Agentic RAG：単一検索ではなく、エージェントが反復検索・ツール利用・再試行で答えを練り上げる進化版RAG。
Function Calling／ReAct：LLMが外部ツールを呼び出しながら推論と行動を繰り返すエージェントパターン。
Beehive アーキテクチャ：Dify v1.0のモジュラー設計 — 各モジュールが独立して稼働・置換可能。
SSO（シングルサインオン）：1回の認証で複数サービスにアクセス — SAML、OIDC、OAuth2に対応。
