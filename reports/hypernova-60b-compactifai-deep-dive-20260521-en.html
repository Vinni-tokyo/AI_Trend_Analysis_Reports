HyperNova 60B 2605 Deep Dive
The State of CompactifAI Quantum-Inspired Compression

Halving a 120B model — how tensor-network compression rewrites the economics of LLM inference
Report date: May 21, 2026 | Deep-Dive Analysis | Data collected: May 21, 2026

Top 5 Trends

Released on Hugging Face on February 26, 2026 by San Sebastián–based Multiverse Computing, HyperNova 60B 2605 is a compressed version of OpenAI's gpt-oss-120b, produced with the quantum-inspired tensor-network technology CompactifAI. This report analyzes the model's technical essence, benchmarks, inference economics, and the global trajectory of the compressed-LLM market.

1. CompactifAI: Quantum-Inspired Tensor-Network Compression

Status: CompactifAI uses tensor-network mathematics, a discipline rooted in quantum physics, to identify mathematical redundancy inside a neural network and rebuild the model while retaining only its most information-rich components. Unlike pruning (removing weights) or quantization (lowering bit width), it is described as "rewriting the blueprint, not removing bricks" (Source: TechRadar, 2026).

Core Principle

• Tensor decomposition: weight matrices factorized into low-rank tensor networks to strip redundancy
• Information retention: only high-information correlations are kept
• Compression rate: up to 95% size reduction with 2–3% precision loss (Source: Multiverse Computing)

Applied to HyperNova

• Parameters: 120B → 59–60B (MoE: 4.8B active/token)
• Weight footprint: 121.54GB → 31.81GB
• License: Apache 2.0 (commercial use allowed)
• Format: Safetensors, BF16/U8 tensor types

2. HyperNova 60B 2605: Recovering Intelligence at Half the Size

Status: Compared with the prior 2602 build, 2605 recovers significant ground on most benchmarks, moving closer to the original 120B. Gains are especially clear on HLE (7.28→14.97), GPQA:d (65.56→71.92), and IFBench (59.40→66.57) — suggesting that post-compression fine-tuning cycles can effectively "win back" capability lost during compression.

Intelligence Benchmarks (vs original 120B)

• AIME25 (math): 90.00 (original 93.67)
• GPQA:d (grad-level science): 71.92 (original 74.64)
• HLE: 14.97 (original 18.50)

2602 → 2605 Improvement

• HLE: +7.69 (more than doubled)
• GPQA:d: +6.36
• IFBench: +7.17
• AIDER (coding): 26.2 → 34.2

3. Inference Efficiency: 64% Less Memory, 36% Higher Throughput

Status: Measured at concurrency 128 on an NVIDIA H200, HyperNova 60B 2605 leads on nearly every metric that determines inference cost. Total memory drops from 123.55GB to 38.83GB (≈ -69%) and model weights from 121.54GB to 31.81GB (≈ -74%) — comfortably fitting a single H200 (141GB) or one 80GB-class GPU.

Speed & Latency

• Throughput: 3,821 → 5,210 tok/s (+36%)
• Output speed: 57.79 → 69.31 tok/s
• E2E latency: 24.05s → 14.74s (-38%)
• Time to first token (TTFT): 7.04s → 4.85s (-31%)

Cost & Infrastructure Implications

• More concurrent requests per GPU → lower cost per token
• Runs on a single 80GB GPU → avoids multi-GPU overhead
• Multiverse claims 50–80% inference cost reduction (Source: Multiverse Computing)

📊 Credibility Assessment:8.5/10
Strengths: Measurement conditions (vLLM 0.13.0, batch size 64) stated, supporting reproducibility
Weaknesses: The 50–80% cost claim varies widely by model and workload

Outlook: As compute-cost pressure mounts across the AI supply chain, "same performance, half the memory" becomes a decisive differentiator in unit-cost competition for inference-heavy services.

Five Market Trends

  • Rise of structural compression: Beyond plain quantization, tensor-network methods that redesign model structure are emerging as a new category.
  • Open-weight compression race: Who can best compress open models (gpt-oss, Llama, DeepSeek) is becoming a core competitive axis.
  • Edge / on-device demand: Memory savings translate directly into on-device and offline feasibility, expanding demand.
  • Inference unit-cost competition: With inference dominating operating cost over training, efficiency is central to cost strategy.
  • API-ization & self-serve: Consuming compressed models via APIs (e.g., the CompactifAI API) — without self-hosting — is spreading.

Key Terminology

Tensor Networks: A mathematical toolset from quantum physics for efficiently representing complex data structures; used here to find and compress redundancy in neural networks.
CompactifAI: Multiverse Computing's compression technology that uses tensor networks to shrink LLMs by up to 95%.
Quantization: A common efficiency technique that represents weights in fewer bits (e.g., 4-bit) to reduce footprint.
MoE (Mixture of Experts): An architecture that activates only some expert sub-networks per token to cut computation. HyperNova activates 4.8B of 60B.
Tool Calling: The model invoking external functions/tools via a defined schema — central to building agents.
TTFT (Time To First Token): Time from request to the first output token; drives perceived responsiveness.
gpt-oss-120b: OpenAI's open-weight 120-billion-parameter model, the base for HyperNova.
