스페인 산세바스티안 기반의 Multiverse Computing이 2026년 2월 26일 Hugging Face에 공개한 HyperNova 60B 2605는 OpenAI의 gpt-oss-120b를 양자 영감(quantum-inspired) 텐서 네트워크 기술 CompactifAI로 압축한 모델입니다. 이 보고서는 모델의 기술적 본질, 벤치마크, 추론 경제성, 그리고 압축 LLM 시장의 글로벌 동향을 종합 분석합니다.

1. CompactifAI: 양자 영감 텐서 네트워크 압축

현황: CompactifAI는 양자물리학에서 출발한 텐서 네트워크(Tensor Networks) 수학을 활용해 신경망 내부의 수학적 중복(redundancy)을 식별하고, 정보 밀도가 높은 구성 요소만 보존하는 방식으로 모델을 재구성합니다. 단순히 가중치를 잘라내는 프루닝이나 비트 수를 낮추는 양자화와 달리 "벽돌을 빼는 것이 아니라 청사진을 다시 쓰는" 접근으로 설명됩니다 (출처: TechRadar, 2026).

핵심 원리

• 텐서 분해: 가중치 행렬을 저차원 텐서 네트워크로 분해해 중복 제거
• 정보 보존: 정보량이 큰 상관관계만 유지
• 압축률: 최대 95% 크기 축소, 정밀도 손실 2~3% 이내 (출처: Multiverse Computing)

HyperNova 적용 결과

• 파라미터: 120B → 59~60B (MoE 활성 4.8B/토큰)
• 가중치 용량: 121.54GB → 31.81GB
• 라이선스: Apache 2.0 (상업적 이용 가능)
• 형식: Safetensors, BF16/U8 텐서 타입

강점: Hugging Face 모델 카드와 다수 언론 보도로 교차 검증된 구체적 수치
개선점: 압축 알고리즘 세부 구현은 비공개(특허)로 독립 재현 검증 한계
🔗 관련 링크: HyperNova 60B 2605 (Hugging Face) | CompactifAI | Multiverse Computing

전망: 텐서 네트워크 압축이 "양자화의 다음 단계"로 자리매김할 경우, GPU 메모리 제약이 큰 온프레미스·엣지 환경에서 채택이 가속될 가능성이 높습니다.

2. HyperNova 60B 2605: 절반 크기로 지능을 회복하다

현황: 동일 모델의 이전 버전인 2602 대비 2605는 대부분의 벤치마크에서 큰 폭으로 점수를 회복하며, 원본 120B에 한층 근접했습니다. 특히 HLE(7.28→14.97), GPQA:d(65.56→71.92), IFBench(59.40→66.57)에서 두드러진 개선을 보였습니다. 이는 압축 후 추가 미세조정(fine-tuning)을 통해 "압축으로 잃은 능력을 되찾는" 반복 개선 사이클이 효과적임을 시사합니다.

지능 벤치마크 (vs 원본 120B)

• MMLU-Pro: 76.77 (원본 79.64, 96% 수준)
• AIME25(수학): 90.00 (원본 93.67)
• GPQA:d(대학원 과학): 71.92 (원본 74.64)
• HLE: 14.97 (원본 18.50)

2602 → 2605 개선폭

• HLE: +7.69 (2배 이상)
• GPQA:d: +6.36
• IFBench: +7.17
• AIDER(코딩): 26.2 → 34.2

📊 신뢰도 평가:8.0/10
강점: 평가 프레임워크(NeMo-Skills, EvalScope), 하드웨어(H200), 설정값까지 공개
개선점: 벤더 자체 측정치로, 제3자 독립 벤치마크 비교 필요
🔗 관련 링크: gpt-oss-120b (원본) | gpt-oss 모델 카드 (arXiv)

전망: 동일 모델을 날짜 버전(2602, 2605)으로 빠르게 반복 배포하는 전략은, 압축 모델도 지속적 업데이트로 품질을 끌어올릴 수 있음을 보여줍니다.

3. 추론 효율: 메모리 64% 절감, 처리량 36% 향상

현황: 동시성(concurrency) 128, NVIDIA H200 환경 측정 기준, HyperNova 60B 2605는 원본 대비 추론 비용을 결정짓는 거의 모든 지표에서 우위를 보입니다. 총 메모리 사용량은 123.55GB → 38.83GB(약 -69%), 모델 가중치는 121.54GB → 31.81GB(약 -74%)로 줄어, 단일 H200(141GB) 또는 80GB급 GPU 한 장에도 여유롭게 적재됩니다.

속도·지연 지표

• 처리량: 3,821 → 5,210 tok/s (+36%)
• 출력 속도: 57.79 → 69.31 tok/s
• E2E 지연: 24.05s → 14.74s (-38%)
• 첫 토큰까지(TTFT): 7.04s → 4.85s (-31%)

비용·인프라 함의

• 동일 GPU에서 더 많은 동시 요청 처리 → 토큰당 비용 절감
• 80GB GPU 1장으로 운용 가능 → 멀티-GPU 비용 회피
• Multiverse는 추론비 50~80% 절감 주장 (출처: Multiverse Computing)

📊 신뢰도 평가:8.5/10
강점: vLLM 0.13.0, 배치 64 등 측정 조건 명시로 재현성 높음
개선점: 50~80% 비용 절감은 모델·워크로드별 편차 큼

전망: AI 공급망의 컴퓨팅 비용 압박이 커지는 가운데, "동일 성능·절반 메모리"는 추론 중심(inference-heavy) 서비스의 단가 경쟁에서 핵심 차별점이 됩니다.

4. 에이전트·코딩 능력: 일부 지표에서 원본 추월

현황: 가장 주목할 결과는 LiveCodeBench에서 68.68점으로 원본 120B(62.75)를 추월한 점입니다. 압축 모델이 일부 작업에서 원본을 능가하는 것은, CompactifAI가 단순 손실 압축이 아니라 압축+재학습으로 특정 능력을 강화할 수 있음을 보여줍니다. 네이티브 툴 콜링(OpenAI 함수 스키마), 구조화 출력, 조절 가능한 추론 강도(low/medium/high)를 지원해 코딩 에이전트에 적합합니다.

에이전트·코딩 벤치마크

• LiveCodeBench: 68.68 (원본 62.75 추월) ✅
• Tau2-bench(통신): 61.70 (원본 63.74)
• SciCode: 36.00
• Terminal Bench: 15.91 (원본 24.24, 약점)

에이전트 기능

• Chain-of-thought 디버깅 가능

5. 글로벌 동향: 엣지 배포와 압축 LLM의 주류화

경쟁 환경과 시장 포지셔닝

LLM 경량화 시장은 접근 방식에 따라 4개 계층으로 구분할 수 있습니다. CompactifAI는 양자 영감 텐서 네트워크라는 독자 기술로 Tier 1에 위치합니다.

주요 플랫폼 역량 비교

시장 트렌드 5가지

  • 구조적 압축의 부상: 단순 양자화를 넘어 모델 구조 자체를 재설계하는 텐서 네트워크 방식이 새로운 카테고리로 부상.
  • 오픈 가중치 압축 경쟁: gpt-oss·Llama·DeepSeek 등 오픈 모델을 누가 더 잘 압축하느냐가 경쟁의 핵심으로 이동.
  • 엣지·온디바이스 수요: 메모리 절감이 곧 온디바이스·오프라인 실행 가능성으로 직결되며 수요 확대.
  • 추론 단가 경쟁: 학습보다 추론(inference) 비용이 운영 부담의 다수를 차지하면서 경량화가 비용 전략의 핵심.
  • API화·셀프서브: 압축 모델을 직접 호스팅하지 않아도 API로 소비하는 흐름(CompactifAI API 등) 확산.

활용 아이디어

시장에서 관찰되는 주요 활용 접근을 소개합니다.

1. 온프레미스 코딩 에이전트 - 80GB GPU 1장에 적재해 사내 보안 환경에서 코드 생성·리뷰 자동화 (LiveCodeBench 강점 활용).

2. 추론 비용 최적화 PoC - 기존 120B 서비스의 일부 트래픽을 60B로 라우팅해 메모리·단가 절감 효과를 A/B 검증.

3. 엣지·오프라인 어시스턴트 - 연결성이 제한된 현장(제조·물류)에서 로컬 LLM으로 RAG·툴 콜링 기반 보조 도구 운영.

핵심 요약 (Executive Summary)

주요 인사이트

  • 절반 크기, 동급 지능: 120B를 ~60B(가중치 31.81GB)로 압축하면서 MMLU-Pro 등 핵심 지표를 원본의 90%대 수준으로 유지.
  • 추론 경제성: 메모리 ~69% 절감, 처리량 +36%, 지연 -38%로 토큰당 비용을 구조적으로 낮춤.
  • 일부 지표 추월: LiveCodeBench에서 원본을 능가 — 압축이 곧 성능 저하라는 통념을 반박.
  • 독자 기술 해자: 양자 영감 텐서 네트워크는 양자화·증류와 차별화된 카테고리이며 특허 160건+로 보호.
  • 상업 모멘텀: $215M 펀딩, 100+ 고객, API 포털·엣지 앱으로 압축 LLM의 주류화 진행.

선택 가이드

추론 비용·메모리가 핵심 제약 → HyperNova 60B 검토
이유: Apache 2.0 라이선스로 자체 호스팅 가능, 80GB GPU 1장 운용.
최고 정확도가 절대 우선 → 원본 gpt-oss-120b 유지
이유: HLE·Terminal Bench 등 일부 작업은 여전히 원본 우위.
이미 양자화 파이프라인 보유 → 벤치마크 직접 비교 후 결정
이유: GPTQ/AWQ 대비 실질 이득은 워크로드별 검증 필요.

종합 평가: 긍정적 — 압축 LLM이 비용·성능 트레이드오프를 실용 수준으로 끌어올린 대표 사례. 단, 벤더 측정치인 만큼 도입 전 자체 워크로드 검증을 권장.

주요 용어 설명

텐서 네트워크(Tensor Networks): 복잡한 데이터 구조를 효율적으로 표현하는 양자물리 유래 수학 도구. 신경망의 중복을 찾아내 압축하는 데 활용됩니다.
CompactifAI: Multiverse Computing의 압축 기술로, 텐서 네트워크를 사용해 LLM 크기를 최대 95%까지 줄입니다.
양자화(Quantization): 가중치를 더 적은 비트(예: 4-bit)로 표현해 용량을 줄이는 일반적 경량화 기법.
MoE(전문가 혼합): 토큰마다 일부 전문가 네트워크만 활성화해 연산을 줄이는 구조. HyperNova는 60B 중 4.8B만 활성.
툴 콜링(Tool Calling): 모델이 외부 함수/도구를 정의된 스키마로 호출하는 기능. 에이전트 구현의 핵심.
TTFT(Time To First Token): 요청 후 첫 토큰이 나오기까지 걸리는 시간. 체감 응답성을 좌우.
gpt-oss-120b: OpenAI가 공개한 오픈 가중치 1,200억 파라미터 모델로, HyperNova의 원본(base) 모델.
