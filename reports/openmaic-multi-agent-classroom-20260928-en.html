Tsinghua's Open Multi-Agent AI Classroom

Top 5 Trends

1. What OpenMAIC Is — It Generates a Classroom, Not an AI Tutor

Where things stand: OpenMAIC (Open Multi-Agent Interactive Classroom) is an open-source platform released by the THU-MAIC team at Tsinghua University. Give it a one-line topic or upload a single PDF, and it produces a complete lesson — slides, quizzes, interactive simulations, and project-based learning (PBL). The distinguishing point is that the output is not study material but a running class: an AI teacher lectures with voice, draws on a whiteboard in real time, and AI classmates join discussions and push back. The repository was created on March 11, 2026, with v0.1.0 shipping on March 26. As of September 28, 2026 it has reached 39,290 stars, 6,102 forks, and roughly 106 contributors (queried directly from the GitHub API). The latest release is v1.1.1, dated September 26.

Measured repository metrics (2026-09-28)

• Stars: 39,290 · Forks: 6,102 · Watchers: 180
• Contributors: ~106 · Open issues: 173
• Primary language: TypeScript · License: MIT
• Created: 2026-03-11 · Last push: 2026-09-27
• 13 releases: v0.1.0 (Mar 26) → v1.1.1 (Sep 26), roughly six months

The four "scene" types it generates

• Slides: narrated lectures with animation
• Quizzes: single-choice, multiple-choice and short answer, with AI grading
• Interactive simulations: HTML-based 3D, physics and flowcharts
• PBL: collaborative projects with defined milestones
• Deep Interactive Mode (v0.2.0+): games, mind maps, in-browser coding environments

Outlook: 39,000 stars in six months is unusual velocity for an education-domain open-source project. But stars measure interest, not production adoption, and public data cannot tell us how many of the 6,102 forks are actually running anywhere.

2. Agent Design — Teacher, Assistant, and Four Classmate Archetypes

Where things stand: The theoretical foundation is the paper "From MOOC to MAIC," posted to arXiv in September 2024 and published in 2026 in the Journal of Computer Science and Technology (JCST, DOI 10.1007/s11390-025-6000-0). In that paper the classroom consists of a teacher agent (aT), a teaching-assistant agent (aTA), and four classmate archetypes, with a Session Controller above them (a Class State Receptor plus a Manager meta-agent) regulating who speaks when. The design is not "one AI tutor teaching one student" but a deliberately staged scene in which several roles talk to one another.

The four classmate archetypes (from the paper)

• Class Clown: stirs the room and handles lapses in attention
• Deep Thinker: raises thought-provoking questions
• Note Taker: summarizes the key points of a discussion
• Inquisitive Mind: draws out inquiry-based dialogue
• Manager meta-agent: decides who speaks and when — the paper states its accuracy remains below optimal levels

Orchestration on the implementation side

• LangGraph state machine manages agent interaction
• Two-stage generation pipeline: outline → scene content
• Action Engine: executes 21 action types — speech, whiteboard, effects and more
• Playback Engine: a separate state machine that drives classroom delivery
• Curriculum Agent (v1.0.0): a conversational workbench that plans the curriculum, builds pages and revises them, backed by 24 reusable skills

📊 Credibility Assessment: 8.5/10
Strengths: Agent roles and the stated design limits come from the authors' own paper (arXiv:2409.03512; JCST 2026); implementation details (21 actions, two-stage pipeline, LangGraph) come from the official repository documentation.
Weaknesses: We did not diff the source to confirm that the paper's four archetypes match the agent set in the v1.x code. The paper describes a 2024 system and the open-source release is from 2026 — two years apart, so details may differ.
🔗 Related Links: arXiv:2409.03512 From MOOC to MAIC | JCST published version | LangGraph

Outlook: The "classmate agent" pattern is worth borrowing for anyone designing recommendation or conversational systems. Rather than asking one model to play every part, roles are separated and turn-taking is adjudicated by a distinct meta-agent. That said, the authors themselves leave that meta-agent's accuracy as an open problem.

3. The Evidence — What the Paper Measured, and What Marketing Copy Rephrased

Where things stand: MAIC ran for real at Tsinghua. The paper's pilot covered two courses — "Towards Artificial General Intelligence" (TAGI) and "How to Study in the University" (HSU) — with 500+ students over 3+ months and 100,000+ behavioral records. One caution matters here. Several overview pages state "validated with 700+ students over 2+ years" or "84.1% satisfaction." Neither figure can be confirmed in the paper. What the paper reports is not a single satisfaction percentage but item-level scores on a five-point scale.

Figures confirmed in the paper

• "The AI instructor clearly communicated course goals": 4.12 / 5
• "Encouraged exploring new concepts": 4.03 / 5
• "Provided feedback on strengths and weaknesses": 3.51 / 5 — the lowest-rated item
• Behavior mix: 61% actively seeking knowledge · 11% managing agents and class progress
• Module test scores: 53.3% – 82.4% · Attendance: 76.3% (modules) / 73.3% (final)

Statistically significant changes

• Message frequency/length ↔ test scores: r = 0.341–0.346 (p<0.001) — correlation, not causation
• Overall technology acceptance rose: t = 3.05, p = 0.002
• Components: Habit p=0.005 · Effort Expectancy p<0.001 · Facilitating Conditions p=0.002
• Higher-order thinking (self-reported): abstract thinking p=0.02 · critical thinking p=0.02
• Follow-up study (arXiv:2508.17310): the CPADP dropout-prediction framework reached up to 95.4% accuracy, validated at a deployment of 3,000+ students

⚠️ Care when citing these numbers: (1) r ≈ 0.34 is a correlation — "students who talked more scored higher," not "making students talk raises scores." (2) "700 students / 2 years / 84.1%" traces to secondary overview pages and cannot be matched against the authors' paper; for external material, the paper's figures (500+ students, 3 months, item-level 5-point scores) are the safe ones. (3) Gains in higher-order thinking are student self-report, not objective measurement — the paper says so explicitly.
📊 Credibility Assessment: 8/10
Strengths: Every figure was read from the paper itself (arXiv HTML version), and the authors' own stated limitations are reproduced here: manager-agent accuracy, identical lecture scripts for all students, self-report-based evaluation, limited peer-to-peer interaction, and possible algorithmic bias.
Weaknesses: This is a pilot observational study, not a controlled experiment with a comparison group, so "better than a MOOC" cannot be claimed from this data. The 95.4% from the follow-up dropout paper is taken from the abstract; its evaluation protocol was not verified.
🔗 Related Links: MAIC paper, full text (HTML) | Dropout-prediction follow-up (CPADP) | Student-AI interaction: cluster analysis

Outlook: That the lowest-scoring item is "feedback quality" (3.51/5) points precisely at the field's next problem. Generating a lesson is largely solved; telling an individual learner what they are good and bad at is not.

4. Stack and License — AGPL to MIT, and Stale Information Still Circulating

Where things stand: The front end is Next.js 16, React 19, TypeScript 5 and Tailwind CSS 4; orchestration is LangGraph 1.1; persistence is a swappable layer across browser, HTTP, PostgreSQL and S3. Supported large language model (LLM) providers number more than sixteen — OpenAI, Azure OpenAI, Anthropic, Amazon Bedrock, Google Gemini, DeepSeek, Qwen, Kimi, MiniMax, Grok, OpenRouter, GLM, Ollama and others — plus any OpenAI-compatible API. The license was changed from AGPL-3.0 to MIT in v0.3.0 (2026-06-29), and the same release published the @openmaic/* SDK packages to npm. Commercial use is permitted under MIT terms.

Deployment, export and integration

• Deployment: one-click Vercel · Docker Compose (PostgreSQL and render-service profiles) · self-hosted servers
• Export: PowerPoint (PPTX) · interactive HTML · classroom ZIP packages · MP4 (render service)
• Optional services: Lemonade (local LLM/TTS/ASR), FunASR (local speech recognition), MinerU (document parsing), VoxCPM2 (self-hosted TTS with voice cloning)
• Internationalization: 12 locales · dark mode
• Agent workbench integration: ships a SKILL.md-format skill package — importable into OpenClaw (clawhub install openmaic), Codex and others, with Feishu, Slack, Telegram and Discord channel support

Conflicting information — don't trust third-party pages

• License: official repository says MIT; some overview sites still say AGPL-3.0 → that predates v0.3.0
• Star count: measured 39,290 vs. overview site 3,700 vs. articles citing 25,975 / 30,000 → different snapshot dates
• License exception: the root is MIT, but packages/mathml2omml is LGPL-3.0-or-later — check separately before redistributing
• Many mirrors: search results are full of personal forks carrying the identical description → the THU-MAIC organization account is the canonical source

📊 Credibility Assessment: 8.5/10
Strengths: The license was settled from the GitHub API license field (spdx_id: MIT) and the switch was dated from the v0.3.0 release notes. Stack, provider list and export formats come from official repository documentation.
Weaknesses: The reason for the AGPL→MIT change is not stated in the public release notes and could not be confirmed, so it is left unexplained rather than guessed. No full audit of sub-package licenses was performed.

Outlook: The MIT relicense, the npm SDK, and the SKILL.md skill package all point the same direction: a strategy of becoming a component other people embed, rather than a finished application. Lifting out only the slide generation or classroom playback and wiring it into an existing LMS or agent workbench is the most plausible first form of adoption.

5. Security — CVE-2026-86259, or How "Convenient Defaults" Bill You in Production

Where things stand: In September 2026, an unauthenticated server-side request forgery (SSRF) vulnerability, CVE-2026-86259, was disclosed for OpenMAIC 1.0.0 and earlier. Two things compounded. First, the shipped defaults (.env.example) leave ACCESS_CODE unset, which leaves all 70 API routes globally unauthenticated. Second, validation of client-supplied provider base URLs (validateUrlForSSRF()) runs only when NODE_ENV === 'production'. In non-production builds, an attacker can therefore use the x-base-url header or the baseUrl query parameter to reach the instance metadata service (IMDS) on AWS, GCP or Azure and pull cloud credentials. It was fixed in 1.0.1 (GHSA-9m7h-vh2h-rc3w), and 1.0.2, 1.0.3 and 1.1.1 were all subsequent security releases.

Vulnerability summary

• ID: CVE-2026-86259 · Affected: ≤ 1.0.0 · Fixed in: 1.0.1
• Type: unauthenticated outbound SSRF → IMDS access
• Input points: x-base-url header, baseUrl query parameter
• Severity: most databases list CVSS 7.5; some analysis sites list 9.3 — sources disagree
• Root cause: fail-open middleware plus environment-gated validation

Deployment checklist

• Version: pin to 1.1.1 or later and put a release-tracking process in place (four security releases in September alone)
• Authentication: ACCESS_CODE must be set — but it is a shared code, not cryptographic protection
• NODE_ENV: production deployments must be production builds
• Egress control: block metadata endpoints such as 169.254.169.254 from the container and enforce IMDSv2
• Asset isolation: the default is a single shared principal per deployment — per-user asset isolation and quotas are not provided out of the box
• Learner data: do not connect real student data until privacy, logging and retention rules are settled

📊 Credibility Assessment: 8/10
Strengths: CVE identifier, affected and fixed versions, attack input points and root cause were consistent across multiple vulnerability databases, and the fix release (v1.0.1) plus four subsequent security releases were confirmed directly in the GitHub release list.
Weaknesses: CVSS scoring splits between 7.5 and 9.3 depending on the source (both are shown above). We did not run a proof of concept to reproduce it, nor verify the patch diff at code level.
🔗 Related Links: Security releases (v1.0.1–v1.1.1) | VulDB CVE-2026-86259 | CVE alert

Outlook: The lesson here is not specific to OpenMAIC. Defaults chosen to make a demo easy shipping straight into production is the characteristic failure shape of fast-growing AI open source, and the same three checks — how many unauthenticated routes exist, which validations are gated on an environment variable, and what egress policy applies — are worth applying to your own LLM services.

Competitive Landscape and Market Positioning

A four-tier market structure

"Learning with AI" is not one market. The competitor set changes entirely depending on whether the output is a running class, study material, tutor conversation, or slides. OpenMAIC stands nearly alone in the first tier and does not compete head-on with the others.

Shifts visible in the market

• From generating artifacts to generating delivery: where Tier 4 stopped at the deck, Tier 1 brings the timeline of a lesson, the order of speech, and the interaction itself into scope.
• Institutional products are strengthening teacher control: the 2026 Khanmigo–Google.org collaboration moved toward teachers generating, reviewing and curating questions before assigning them (Practice My Knowledge) — human review retained, not removed.
• Reduced model lock-in has become a competitive factor: OpenMAIC's 16-plus provider support and its Ollama/Lemonade local paths are preconditions for institutional adoption where regulation or data sovereignty applies.
• Open source has reached the education domain: Tiers 1, 2 and 4 all now have a self-hosting option; Tier 3 is the only one that remains managed-only.

Application Ideas

Approaches observed in the market.

1. Export-path-only pilot — feed in existing course PDFs, validate no further than PPTX/HTML/ZIP export, and measure model API cost per lesson to establish unit economics first.

2. Borrow the role-separation design — treat the teacher/assistant/four-classmate structure, with a meta-agent adjudicating turn order, as a reference model when designing recommendation or learning-dialogue scenarios.

3. Turn the vulnerability into a baseline — convert the three elements of CVE-2026-86259 (count of unauthenticated routes, validations gated on environment variables, metadata egress) into a review checklist for your own LLM services.

Executive Summary

Key findings

  • The substance is real: Tsinghua THU-MAIC's OpenMAIC reached 39,290 stars, 6,102 forks and roughly 106 contributors within six months of its March 2026 release — an MIT-licensed TypeScript project (measured via API on 2026-09-28), with 13 releases and v1.1.1 as the latest.
  • The output is different in kind: where competing tools produce material or slides, OpenMAIC generates the class itself, delivered by teacher, assistant and classmate agents. Four scene types (slides, quizzes, simulations, PBL) and 21 action types are orchestrated through a LangGraph state machine.
  • There is evidence, but not a controlled trial: the paper (JCST 2026) is a pilot observation with 500+ students over three months and 100,000+ records. Satisfaction is item-level — 4.12, 4.03, 3.51 out of 5 — and the link between participation and scores is a correlation of r ≈ 0.34. With no comparison group, "better than a MOOC" cannot be claimed from this data.
  • The weakest score points to the next problem: the lowest item is "feedback on strengths and weaknesses" at 3.51/5. Lesson generation is solved; individual diagnostic feedback is the open work.
  • Security is a precondition for adoption: the unauthenticated SSRF in ≤1.0.0 (CVE-2026-86259) left 70 API routes open by default and could reach cloud metadata. It is fixed in 1.0.1, but September alone saw four security releases — production deployment is not viable without version pinning and release tracking.
  • Secondary sources will mislead you: third-party overview pages list the license as AGPL, stars as 3,700, and validation as "700 students / 2 years / 84.1% satisfaction." Cross-check against the official repository and the original paper.

Selection Guide

If self-hosting, model choice and customization come first → OpenMAIC
Why: MIT license, 16-plus providers plus local paths via Ollama and Lemonade, swappable PostgreSQL/S3 persistence — on the condition that you establish a security baseline first.
If you need teacher-controlled adoption in a school or institution → Khanmigo / Gemini for Education
Why: managed operation, admin controls and workspace integration, and a teacher-review flow (generate questions, then review and curate) that is already designed in.
If an individual simply needs to absorb material quickly → the NotebookLM tier
Why: no classroom staging required; summaries, flashcards and audio overviews are sufficient.
If all you need is an editable deck → Presenton (open source) / Gamma
Why: if the goal is PPTX or PDF output with no interactivity and no agents, OpenMAIC is overkill.

Key Terminology

MOOC / MAIC — A MOOC is an open online course where many people watch the same recorded lecture. MAIC (Massive AI-empowered Course) turns that lecture into something AI agents deliver live, aiming to keep the scale while adding individual responsiveness.
Multi-agent orchestration — Having several AIs with different roles cooperate within one task, in a defined order and under defined conditions. Assigning separate teacher, assistant and classmate roles and deciding separately who speaks when is one example.
LangGraph — An open-source framework that defines agent flow as a state machine (a graph). It manages "which step are we on" explicitly, which suits long conversations and work that pauses and resumes.
PBL (project-based learning) — Learning by working through a task rather than by listening to a lecture. OpenMAIC generates collaborative projects with defined milestones as one of its scene types.
SSRF (server-side request forgery) — An attack that tricks a server into sending requests, in the server's own name, to internal addresses. The point is to reach internal resources an outsider cannot touch directly, by using the server as a stepping stone.
IMDS (instance metadata service) — The internal-only address a cloud virtual machine uses to look up its own configuration and temporary credentials. Reaching it via SSRF can leak cloud access, which is exactly why the vulnerability above mattered.
MIT / AGPL-3.0 licenses — MIT is permissive: keep the copyright notice and you may use, modify and redistribute commercially, including in closed form. AGPL-3.0 is strong copyleft that requires source disclosure even when the software is offered as a network service. OpenMAIC moved from the latter to the former in v0.3.0.
TTS / ASR — TTS reads text aloud (the AI teacher's lecture voice); ASR transcribes speech into text (recognizing what a student says). OpenMAIC supports both via external APIs and via self-hosted options (VoxCPM2, FunASR).
