競い合っていた規格が
同じ屋根の下へ向かう理由

財団が引き受けた役割、そしてその仕組みが持つ力と限界
レポート作成日：2026年10月9日 | 標準レポート（5-8ページ） | データ収集：2026年10月9日

主要トレンド Top 5

本レポートの中心的な主張
一つの会社が作った技術が「業界標準」になるには、その会社の手を離れる必要があります。 財団はその移管を受け入れる中立の場であり、いま AI の分野でその移動が一度に起きています。 本レポートは財団を並べ上げるのではなく、なぜ企業が自社の資産を手放すのかと その仕組みが何を保証し、何を保証しないのかを扱います。

1. 競合三社が一つの財団を共に設立した — Agentic AI Foundation

現状：2025年12月、Linux Foundation が Agentic AI Foundation（AAIF） の設立を発表しました。 注目すべきは設立の仕方です。器を先に作って案件を集めたのではなく、 三社がそれぞれの中核資産を持ち寄り、それによって財団が立てられました。

設立時の寄贈案件

• MCP — Anthropic の Model Context Protocol
• goose — Block のエージェント向け道具
• AGENTS.md — OpenAI が寄贈
三社は市場で互いに競い合っています。その三社が設立メンバーとして同じ名の下に並んだことが、 この出来事の本質です。

集まった顔ぶれ

• 設立：OpenAI・Anthropic・Block
• 後援：Google・Microsoft・AWS・Bloomberg・Cloudflare
• 構造：AAIF は Linux Foundation の下の指定基金（directed fund）です
• その後：Google の A2A が2026年8月17日にこの財団のホスティング案件として加わりました

ここに一年前の動きを加えると絵が完成します。 Cisco・LangChain・LlamaIndex・Dell・Oracle・Red Hat が集まった AGNTCY 連合は、 2025年7月に ACP を Linux Foundation へ寄贈しました。 エージェント分野の主要な規格三つが、一年あまりの間にすべて同じ傘の下へ入ったことになります。

🔗 関連リンク: AAIF 設立発表（Linux Foundation） | Anthropic — MCP の寄贈 | OpenAI — AGENTS.md の寄贈

展望：規格をめぐる争いが財団の中に入ると、争いの性格が変わります。 市場で相手を押し出す競争ではなく、同じ机で議席と意思決定の手続きをめぐる競争になります。

📊 信頼性評価： 9/10
強み：Linux Foundation の報道発表、Anthropic と OpenAI それぞれの公式発表、TechCrunch の報道（2025年12月9日）がすべて一致します。設立案件と参加企業が一次資料で確認できます。
改善点：AAIF の指定基金という形が、通常の Linux Foundation 案件と統治の面でどう異なるかは、公開資料では詳しく確認できませんでした。

2. 財団は何をしてくれるのか — 中立性・商標・法務・運営

現状：企業が財団に案件を渡すとき受け取るものは、思いのほか具体的です。 財団はどの一社も過度な支配力を持たないように案件を公式に管理するために作られた組織です。 その役割は宣言ではなく実務によって果たされます。

財団が提供するもの

• 法務・ライセンス支援：ライセンスの整理、貢献者の同意処理
• 商標の管理：名称とロゴを誰がどう使えるかの整理
• 案件運営の道具：すでに整った協働の基盤と手続き
• 行事の支援：共同体が集まる場
• 中立性という合図：「一社のものではない」という事実そのものが採用を助けます

手放すもの

ソフトウェアを寄贈することで、企業はそのソフトウェアへの支配を手放します。
• 他の財団会員に同じ権利が与えられます
• その会員には競合他社が含まれます
• 方向を単独で決められなくなり、手続きに従う必要が生じます
これが寄贈の本質的な代価です。

あわせて読む — 本サイトの2026年10月9日のレポート 「規格争いは起きなかった — MCP と A2A の役割分担」は、 二つの規格が競争ではなく層の分担で決着したと記しました。 その決着を可能にした制度的な装置が、まさにこの財団の仕組みです。 一方が他方に勝つ必要がなくなったのは、どちらも一社のものではなくなったからです。

展望：中立性はただでは手に入りません。支配権と引き換えに得たものであり、 その取引が成り立つ理由は一社が持つ標準より、皆が使う標準のほうが大きいからです。

📊 信頼性評価： 8/10
強み：財団が提供する法務・商標・運営の支援と、「支配を手放し競合に同じ権利を与える」という代価は、オープンソースの統治に関する研究資料で確認できます。
改善点：どの支援が実際に最も決定的かを示す定量資料は得られていません。

3. 種類が違えば決めることも違う — 五つの枝の地図

現状：「財団」と「標準化機関」はしばしば混ぜて語られますが、やっていることが違います。 どこに何があるかを分けておくと、どの問いを誰に向けるべきかがはっきりします。

公式に認められている側

• ISO・IEC・ITU — 国際的に公式に認められた標準化機関です。 ISO/IEC 42001 のような認証が可能な規格を出します
• これらが出すのはde jure（公式）標準です
• 認証書が発行され、規制が参照できます

公式認定ではないが広く使われる側

• W3C・IETF・IEEE・OASIS・OMG
• W3C は厳密には標準化機関ではありません。専門家の集まりが勧告（Recommendation）を出し、 その実装を強制する力は持ちません。ただしほとんどが事実上の標準として受け入れられています
• IETF は RFC でインターネット標準を定め、IEEE はイーサネットなどの LAN 標準を出します

ここにオープンソース側の二つの枝と分野特化の協議体を加えると五つになります。 Linux Foundation・Apache・Eclipse のような統治財団、 その下の CNCF・Agentic AI Foundation・PyTorch Foundation・LF AI & Data・OpenSSF のような分野別財団、 そして 1EdTech（Open Badges・CLR）、HL7（医療）、OGC（空間情報）のような分野特化の協議体です。

区別の実益は明らかです。財団はコードと共同体を運営し、標準化機関は規格を公認します。 de facto として定着したのち de jure へ移る道筋もあります。PDF が ISO へ、HTML が ISO/IEC へ進んだのがその例です。

🔗 関連リンク: Linux Foundation | Apache Software Foundation | CNCF | W3C | IETF | 1EdTech

展望：AI の規格が財団で落ち着くと、次の段階は公認機関への移動である可能性が高いと見られます。 規制が参照できる形が必要になるためです。

📊 信頼性評価： 8/10
強み：ISO・IEC・ITU の公式認定の地位、W3C が勧告を出す機関であること、de facto から de jure への移行事例（PDF・HTML）が標準化の研究資料で確認できます。
改善点：五つの枝という区分自体は本分析による整理です。公認された分類体系ではなく、境界が重なる組織もあります。

4. 企業はなぜ手放すのか — 支配を失って何を得るのか

現状：寄贈は利他的な行為ではありません。計算の立った取引です。 MCP の事例がその計算をよく示しています。Anthropic が支配権を手放したのち、 MCP は月間 SDK 取得が4億回を超え、フォーチュン500の28%が導入する規格になりました。 一社の接続方式のままなら届かなかった数字です。

得るもの

• 中立性という資格：競合他社が採用できるようになります。これが最も大きいものです
• 採用の速さ：「誰のものでもない」が導入の決裁を容易にします
• 法的負担の分散：商標とライセンスの管理を財団が担います
• 継続性：作った会社の事業方針が変わっても規格は残ります

失うもの

• 方向を決める権利：単独では決められず、手続きに従う必要があります
• 速さ：合意が要る分だけ遅くなります
• 差別化：競合他社も同じ規格を使います
それでも手放す理由は明快です。標準になれなかった技術の支配権は、価値が小さいからです。

競合三社が AAIF を共に設立したのも同じ計算です。 エージェントの生態系が分断されれば全員が損をします。 各自が自社の規格を握っているより、共通の規格の上で製品として競うほうが三社すべてにとって大きいのです。

🔗 関連リンク: TechCrunch の報道 | AGNTCY

展望：この計算が成り立つのは市場がまだ固まっていないときです。 勝者が決まったあとは寄贈の誘因が消えます。いま移管が集中しているのは、エージェント市場が形成期にあるという合図でもあります。

📊 信頼性評価： 7/10
強み：寄贈の損得の構造（中立性の獲得と支配権の喪失）はオープンソース統治の研究で確認でき、MCP の普及数値も複数の出典で確認できます。
改善点：「競合三社が共に設立した理由」の解釈は本分析の推論です。各社の公式説明は中立的な発展と標準化という一般的な表現にとどまっています。

5. 財団にあるから安全とは限らない — 仕組みの限界

現状：「財団案件」という札は中立性を意味しますが、その中立性の性格は財団ごとに異なります。 最も鮮明な対比は Linux Foundation と Apache Software Foundation の間にあります。 どちらも広く信頼されていますが、誰が決めるのかが正反対です。

Linux Foundation — 企業会員制

• 法的性格：501(c)(6) 業界団体
• 会員：企業中心、階層型の後援
• 会費：Silver 5,000〜20,000ドル（従業員数による）・Gold 100,000ドル・Platinum 500,000ドル
• Platinum には理事会の議席が含まれます
• 大口の後援企業が統治の議席を持ち、方向に関与する仕組みです

Apache Software Foundation — 個人の実績制

• 法的性格：501(c)(3) 慈善団体
• 会員：個人。資格は継続的な貢献の実績によってのみ得られます
• pay-to-play を厳しく禁じています — 数百万ドルを出しても技術の方向への影響力はゼロであり、コードを寄与した個人のみが投票権を持ちます
• 運営：年およそ 229万ドル規模の企業後援、分散した案件管理委員会（PMC）

ここで読み取るべきは優劣ではなく性格の違いです。 企業会員制は資源を集め、業界の合意を速く作ることに強く、 個人の実績制は特定企業の影響に対してより頑健です。 どの財団にあるかを知れば、その案件の方向が誰の手にあるかもわかります。

そのほかに併せて見るべき限界が三つあります。 意思決定の速さは合意の仕組みである分だけ遅くなり、 フォークの可能性は公開ライセンスである限り常に残り、 何より「財団にある」という事実がコードの品質や安全性を保証するわけではありません。 財団は統治を提供するのであって、監査を代わりにしてくれるわけではありません。

🔗 関連リンク: Apache Software Foundation | Linux Foundation | OpenSSF

展望：AI の規格が財団へ集まるにつれ、「どの財団か」が次の問いになります。 企業会員制の下に置かれた規格は大口後援企業の利害により敏感にならざるをえず、 その感度を知ることが導入組織の危険管理に入ってきます。

📊 信頼性評価： 8/10
強み：会費の区分、501(c)(6)と501(c)(3)の違い、Apache の pay-to-play 禁止と個人実績制は、各財団の公開資料および統治分析で確認できます。
改善点：「大口後援企業の影響が実際の技術判断をどれだけ変えたか」を示す事例研究は今回得られませんでした。構造上の可能性を述べたものであり、特定事例の告発ではありません。

競争環境と市場ポジショニング

五つの枝の地図 — 誰が何を決めるのか

各種類が決められることと決められないことを並べると、どの問いをどこへ向けるべきかがはっきりします。 （分類は本分析による整理であり、境界が重なる組織もあります。）

種類 代表 決めること 決められないこと
① オープンソース統治財団 Linux Foundation、Apache、Eclipse 案件の運営手続き、商標、ライセンス、共同体の規則 法的効力を持つ公認規格 — 認証書は出せません
② 分野別財団 CNCF、Agentic AI Foundation、PyTorch Foundation、LF AI & Data、OpenSSF 当該分野の案件の受け入れと卒業、技術運営委員会の構成 上位財団の会員・会費の仕組みは変えられません
③ 公式標準化機関 ISO、IEC、ITU de jure 標準、認証が可能な規格（例：ISO/IEC 42001） 実装を自ら作ったりコードを運営したりはしません
④ ウェブ・インターネット標準 W3C、IETF、WHATWG 勧告と RFC — 事実上の標準になります 実装を強制する力がありません（W3C は厳密には標準化機関ではありません）
⑤ 分野特化の協議体 1EdTech、HL7、OGC 当該産業のデータ規格と適合性の認証 産業の外ではほとんど拘束力がありません

主要用語の説明

財団（Foundation） — オープンソース案件を一社の所有ではない状態で運営するために作られた組織です。法務・商標・運営を担います。
指定基金（Directed Fund） — 上位財団の中に特定の目的のために作られる下位組織です。Agentic AI Foundation は Linux Foundation の中の指定基金です。
de jure 標準 — ISO のように公式に認められた機関が出した標準です。認証書を発行でき、規制が参照できます。
de facto 標準 — 公式の承認はないものの広く使われ、事実上の標準になったものです。PDF や HTML のように後から公式標準になる場合もあります。
501(c)(6)・501(c)(3) — 米国の非営利組織の法的分類です。(c)(6)は業界団体、(c)(3)は慈善団体で、会員構造と税制が異なります。
pay-to-play — 金銭を出せば意思決定に影響を及ぼせる仕組みを指します。Apache はこれを禁じ、Linux Foundation は後援の等級に議席を結びつけています。
フォーク（Fork） — オープンソース案件を複製して別の方向へ発展させることです。公開ライセンスである限りいつでも可能で、統治に対する最後の歯止めでもあります。
