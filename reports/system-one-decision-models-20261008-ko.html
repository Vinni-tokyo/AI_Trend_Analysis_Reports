Jev·Laya 와 「System One」 범주가 생긴 3주

말하지 않고 판정하는 모델: 25종 넘는 오픈 클론, Ollama 와이어 포맷 표준화, 그리고 2023년 분류기가 Jev 를 이긴 첫 독립 벤치마크

주요 트렌드 Top 5

1. Jev — 글을 쓰지 않고 「판정」을 돌려주는 모델

현황: TypeSafe AI 가 2026년 9월 15일 Jev 를 공개하며 스스로 「System One 모델」이라는 범주명을 붙였습니다. LLM 이 문장을 생성하는 대신, Jev 는 텍스트에 대한 타입이 정해진 질문에 확률과 함께 답합니다. 소프트웨어가 그 값을 그대로 분기 조건으로 쓸 수 있다는 것이 요점입니다. 같은 날 TypeSafe 는 DCVC 주도 4,000만 달러 시드로 스텔스를 벗었고, Forbes 는 투자 후 기업가치를 약 2억 달러로 보도했습니다. 창업자는 전 OpenAI 연구자이자 RLHF·ChatGPT 공동 개발자인 Diogo Almeida, 그리고 Erik Gafni·Sasha Sheng 입니다.

질문 유형 3종 (프리미티브)

• Choice: 최대 255개 선택지 중 하나 + 선택지별 확률 분포
• Score: 순서가 있는 평가 기준 위의 위치(2~10단계) + 단계별 분포
• Noul: 조건이 참일 확률(예·아니오)
• 세 유형 모두 신뢰도 값을 함께 반환
• 학습법은 RLCD(Reinforcement Learning for Calibrated Decisions) — 「선호되는 대화 응답」이 아니라 「판정과 쓸 만한 확률 추정」을 목표로 한 사후학습

공식 문서 기준 운영 스펙

• 버전: jev-1.13.0, 엔드포인트 POST /v1/systemone
• 컨텍스트: 요청당 64k 토큰, state+최장 질문은 32k 예산
• 병렬 평가: state 를 한 번 읽고 모든 질문을 병렬로 판정
• 요율: 입력 100만 토큰당 $0.042 · 출력 토큰 무료
• 한도: 초당 10만 토큰 / 초당 80요청
• 제약: 텍스트 전용(이미지·음성 미지원), 주 언어는 영어, 계정별 파인튜닝 없음(전 고객 동일 가중치)

⚠️ 검증되지 않은 수치 한 건: Sequoia 파트너 Pat Grady 가 「Jev 가 7일 만에 0 → 매출 1억 달러」라고 언급했고 일부 매체가 이를 그대로 실었습니다. 본 보고서는 이 수치를 채택하지 않습니다. 같은 시기 공시된 시드는 4,000만 달러이고 투자 후 기업가치가 약 2억 달러인데, 시드 단계 회사가 주당 1억 달러 매출을 낸다면 그 기업가치와 양립하기 어렵습니다. TypeSafe 는 고객사를 하나도 공개하지 않았습니다.
📊 신뢰도 평가: 9/10
강점: 스펙·요율·한도·제약은 TypeSafe 공식 문서(docs.typesafe.ai/models)에서, 투자 사실은 Business Wire 배포 원문에서 확인했습니다. 창업자 이력도 같은 배포문 기준입니다.
개선점: 파라미터 수·아키텍처·RLCD 세부는 비공개로, 「왜 빠른가」를 검증할 수 없습니다. 지연시간 수치는 공식 문서에 아예 없습니다.
🔗 관련 링크: TypeSafe 공식 모델 문서 | $40M 시드 발표 (Business Wire) | RLCD 해설 (Turing Post)

전망: Jev 의 진짜 발명은 모델이 아니라 인터페이스일 가능성이 높습니다. 「타입이 정해진 질문 3종 + 확률」이라는 계약은 뒤에 어떤 모델이 있든 성립하고, 실제로 3주 만에 그 계약을 구현한 모델이 25종 넘게 나왔습니다.

2. 3주 만의 클론 러시 — Laya 를 포함해 오픈 가중치 25종 이상

현황: Jev 공개 3일 뒤인 2026년 9월 18일, Convai Innovations 가 Laya 의 가중치를 Apache 2.0 으로 Hugging Face 에 공개했습니다. Laya 는 Jev 와 접근이 근본적으로 다릅니다. LLM 을 줄인 것이 아니라 인코더(BERT 계열)에 타입 판정 헤드를 붙인 비자동회귀 모델로, 텍스트를 생성하지 않고 단일 순전파로 답을 냅니다. 영어용 ModernBERT-large 421M, 100개 이상 언어용 mmBERT-base 322M, 그리고 문자 체계를 감지해 적절한 모델로 보내는 라우터로 구성됩니다. 이후 한 달 사이 Jev 의 질문 유형 3종을 그대로 구현한 오픈 모델이 쏟아졌습니다.

Laya 실측 스펙 (HF 모델 카드)

• 구성: 421M(영어) / 322M(다국어) / 421M(typed-decisions 파인튜닝판)
• 라이선스: Apache 2.0 · 실행: CPU·CUDA·Apple Silicon
• 지연: 단건 약 33ms, 배치 시 질문당 7.2ms
• 비용: 자체 하드웨어에서 토큰당 $0 (인프라 비용만)
• 컨텍스트: 영어 512 / 다국어 1,024 토큰 — Jev 의 64k 와 자릿수가 다름
• 학습 규모: 1,200케이스(6,000판정)로 파인튜닝, 400케이스(2,000판정)로 평가

파생 모델 스펙트럼 (일부)

• Decider (Mapika): Qwen3.5 기반 2B/4B/35B-a3b — 35B 는 활성 3B·라우팅 전문가 256개 중 8개 활성
• Nimble (Bespoke Labs): 9B, Qwen3.5-9B 파인튜닝, 8,192 토큰, 선택지 255개
• Clef (Cloudflare, 10-01): 27B/9B Apache 2.0, Workers AI, 100만 토큰당 $0.09
• Anarkali (ToufiqQureshi): 68M — 최소 인코더, 1/6 크기로 Jev 를 앞선다고 주장
• AnyJev (Nokia Applied Research): 학습 불필요 — 기존 LLM 의 은닉상태를 읽어 디바이어싱
• Jev-Omni: 12B 멀티모달(텍스트·이미지·음성·영상) — Jev 가 못 하는 영역

📊 신뢰도 평가: 8/10
강점: Laya 수치는 Hugging Face 공식 모델 카드(convaiinnovations/laya-typed-decisions)에서 직접 확인했습니다 — 학습·평가 케이스 수, 워크플로별 정확도까지 1차 자료입니다.
개선점: 25종 넘는 파생 모델 목록은 단일 집계 사이트를 주 출처로 했고 개별 저장소를 전수 검증하지 않았습니다. 「1/6 크기로 Jev 를 앞선다」류의 주장은 모두 공개자 자체 평가입니다.
🔗 관련 링크: Laya (Hugging Face) | laya-typed-decisions 모델 카드 | Decider (GitHub) | Nimble (Ollama)

전망: 이 클론 러시의 의미는 「누가 이겼나」가 아니라 진입 장벽이 사실상 없다는 사실의 증명입니다. 68M 인코더부터 35B MoE 까지, 심지어 학습이 전혀 필요 없는 방식(AnyJev·SemIf)까지 같은 계약을 만족시켰습니다.

3. 와이어 포맷의 표준화 — Ollama 가 /v1/systemone 을 넣었다

현황: 2026년 9월 29일, Ollama 0.35 가 /v1/systemone 엔드포인트를 추가했습니다. 중요한 점은 이것이 Jev 의 와이어 포맷과 호환된다는 것입니다. 상용 API 의 요청·응답 형식이 2주 만에 로컬 런타임의 표준 엔드포인트가 된 셈입니다. 같은 날 OpenAI 가 Decisions API(GPT-6 Luna 계열, 지연 150ms, 제한 프리뷰)를, Liquid AI 가 d1 을 내놓았고, 이틀 뒤 Cloudflare 가 Clef 를 공개했습니다. 즉 범주가 생긴 지 2주 만에 하이퍼스케일러 3곳이 들어왔습니다.

Ollama 0.35 (2026-09-29)

• 엔드포인트: /v1/systemone — 입력 텍스트·질문·선택지를 함께 전달
• 응답: 산문이 아니라 타입 답변 + 확률 + 사용량
• 질문 유형: choice · noul · score (Jev 와 동일 명칭)
• 초기 탑재 모델 3종: Nimble 9B(Bespoke Labs), Together AI 의 Tev1 4B 와 0.8B(실험판)
• 효과: 로컬 실행 시 추가 비용 0 + 지연 감소 — 티켓 분류·모델 라우팅·콘텐츠 중재 용도

같은 주에 들어온 플랫폼 3곳

• OpenAI Decisions API (09-29): GPT-6 Luna 변종, 150ms, 제한 프리뷰, API 전용
• Liquid AI d1 (09-29): 무료 티어 제공, 자칭 Jev Decision Index 1위
• Cloudflare Clef (10-01): Qwen 파인튜닝 27B/9B, Apache 2.0, Workers AI + 자체 호스팅, 100만 토큰당 $0.09
• 의미: 엣지(Cloudflare)·프런티어(OpenAI)·로컬(Ollama) 세 경로가 같은 인터페이스로 동시에 열렸습니다

📊 신뢰도 평가: 8.5/10
강점: Ollama 0.35 의 엔드포인트 추가와 초기 탑재 모델 3종은 복수의 독립 보도에서 일치했고, 엔드포인트 경로명이 TypeSafe 공식 문서의 POST /v1/systemone 과 동일하다는 점은 직접 대조로 확인했습니다.
개선점: OpenAI Decisions API 와 Liquid AI d1 은 제한 프리뷰·자체 순위 기반이라 1차 문서로 스펙을 확정하지 못했습니다. 「Jev Decision Index 1위」는 벤더 주장입니다.
🔗 관련 링크: Ollama 릴리스 | Nimble on Ollama | Cloudflare Workers AI | Liquid AI

전망: 범주의 승자는 아직 정해지지 않았지만 인터페이스는 이미 정해진 것으로 보입니다. 와이어 포맷이 표준화되면 모델은 교체 가능한 부품이 되고, 경쟁축은 모델 품질보다 지연·단가·배치 위치로 내려갑니다. 이는 Jev 에게 불리한 구조입니다.

4. 첫 독립 벤치마크의 역풍 — 2023년 DeBERTa 분류기가 Jev 를 이겼다

현황: 2026년 10월 2일 Red Hat 개발자 블로그가 4개 계열 9개 모델을 같은 조건에서 비교한 결과를 공개했습니다. NeMo Guardrails 평가 벤치마크의 균형 데이터셋 두 개(프롬프트 인젝션, 유해성·안전)에서 측정했고, 결론은 단호합니다 — 「Jev 같은 의사결정 모델이 LLM-as-a-judge, 사전학습 예측 모델, 오픈소스 의사결정 모델을 속도나 정확도에서 안정적으로 능가하지는 못한다.」

프롬프트 인젝션 (정확도 / 지연)

• Qwen3.6-35B (LLM-as-judge): 89.31% / 312.5ms
• deberta-v3-base-prompt-injection-v2: 89.01% / 54.1ms ← 가장 빠름
• DiffusionGemma-26B: 87.72% / 561.7ms
• Jev-1.13.0: 86.35% / 348.1ms
• Laya: 85.44% / 119.3ms
• → 2023년 계열의 작은 전용 분류기가 정확도는 2.7%p 높고 지연은 1/6

콘텐츠 안전 (정확도 / 지연)

• Jev: 86.20% ← 1위 / 360.4ms
• DiffusionGemma: 85.53% / 499.3ms
• Qwen3.6-35B: 85.47% / 307.6ms
• Nemotron-3.5 (커스텀): 85.07% / 241.5ms
• granite-guardian-hap-125m: 80.27% / 33.2ms
• → Jev 가 1위지만 125M 모델 대비 11배 느리고 격차는 5.9%p

📌 이 벤치마크를 읽는 법: 저자들 스스로 두 가지를 인정합니다. ① 「LLM-as-a-judge 에 맞는 프롬프트 방식이 제로샷 분류기에는 최적이 아니다」 — 실제로 Laya 는 정책 문구를 조정하자 57.87% → 75.20% 로 올랐습니다(같은 모델, 같은 데이터). ② GPU 클러스터 모델은 최소 56ms 대서양 왕복 지연이 포함돼 로컬 CPU 실행과 지연을 직접 비교할 수 없습니다. 즉 이 표는 「모델 서열」이 아니라 「기본값으로 쓰면 무슨 일이 생기나」의 기록으로 읽어야 합니다.
📊 신뢰도 평가: 9/10
강점: 벤더가 아닌 제3자(Red Hat)가 방법론·데이터셋·모델 버전·지연 측정 조건을 공개한 유일한 비교입니다. 저자들이 자기 결과의 한계(프롬프트 방식 미숙, 네트워크 지연 혼입)를 명시한 점도 신뢰를 높입니다.
개선점: 과제가 가드레일 두 종류로 한정돼 Jev 가 내세우는 업무 판정(티켓 분류·청구 처리)은 측정되지 않았습니다. 단일 실행이며 반복 측정의 분산이 제시되지 않았습니다.
🔗 관련 링크: Red Hat 독립 벤치마크 (2026-10-02) | deberta-v3-base-prompt-injection-v2 | NeMo Guardrails

전망: 가드레일처럼 과제가 고정돼 있고 레이블된 데이터가 있는 영역에서는 전용 소형 분류기가 여전히 우세합니다. 의사결정 모델의 값은 그쪽이 아니라, 레이블이 없고 질문이 계속 바뀌는 영역에 있습니다.

5. 진짜 쟁점은 정확도가 아니라 캘리브레이션과 일반화

현황: 수치를 나란히 놓으면 이 범주의 실제 대립축이 드러납니다. typed-decisions 벤치마크에서 파인튜닝한 Laya 는 정확도 0.766 으로 Jev(0.727)를 앞섭니다. 그런데 캘리브레이션 오차(ECE)는 Laya 0.213 vs Jev 0.144 로 Jev 가 낫고, 범용 의도분류 Banking77 에서는 Jev 0.870 vs Laya 0.425 로 격차가 두 배입니다. 그리고 결정적으로 Laya 의 제로샷 정확도는 0.362 — 즉 Laya 는 범용기가 아니라 전용기입니다. 모델 카드도 「네 개 워크플로 밖에서는 성능이 떨어진다」고 직접 적고 있습니다.

Laya 파인튜닝판 세부 (모델 카드)

• 전체: 정확도 0.766 · soft 0.471 · Brier 0.062 · ECE 0.213 · Score MAE 0.242
• 워크플로별: 청구서 0.804 · 보안사고 0.766 · 고객응대 0.764 · 에이전트 추적 0.730
• 질문 유형별: noul 0.857 · choice 0.733 · score 0.723 ← 가장 약함
• 자기 고백: 「확률 분포가 과신(overconfident)」, 온도는 학습데이터로 맞춘 값이므로 홀드아웃으로 재조정 후 쓸 것
• 권고: choice 선택지는 20개 이하로

캘리브레이션이 왜 정확도보다 중요한가

• 운영 라우팅은 신뢰도에 임계값을 걸어 동작합니다
• 따라서 「과신하는 96% 모델」은 「정직한 94% 모델」보다 실무에서 나쁩니다 — 임계값이 의미를 잃기 때문
• accept/escalate 설계: 논문 「JEV-as-a-Judge」(arXiv:2609.26550, Li·Miao·Krishnan·Padman)는 확신할 때 자체 확정, 불확실할 때만 상위 심판으로 올리는 구조를 평가 — 임계값에 따라 20~40% 가 상위로 에스컬레이션
• 단, 논문 역시 「임계값 조정은 과제·도메인 의존」이라고 한계를 명시

🔍 열기와 사용량의 간격: Jev 는 X 에서 4,000만 조회를 기록했고 오픈 클론은 25종을 넘겼습니다. 그런데 Laya 의 typed-decisions 체크포인트는 월 다운로드 722건입니다(HF 모델 카드, 2026-10 기준). 또한 Laya 가 공개한 모든 지표는 Convai Innovations 자체 평가이며, 2026년 10월 현재 제3자 연구기관이 재현한 사례가 없습니다. 커뮤니티의 가장 큰 반론도 이 지점입니다 — r/LocalLLaMA 와 Hacker News 에서는 「캘리브레이션된 확률을 내는 분류기는 이미 풀린 문제이고, TypeSafe 는 흥미로운 주장을 검증할 만큼의 아키텍처를 공개하지 않았다」는 지적이 가장 많이 나왔습니다.
📊 신뢰도 평가: 8.5/10
강점: Laya 수치 전부와 자기 고백(과신·온도 재조정 권고·선택지 20개 권고)은 공식 모델 카드 1차 자료이고, 다운로드 722건도 같은 페이지에서 확인했습니다. accept/escalate 구조는 arXiv 논문 본문 기준입니다.
개선점: Jev 의 typed-decisions 정확도가 출처에 따라 0.727 과 67.8% 로 갈립니다(본문에 양쪽 표기). 이 벤치마크 자체가 Laya 측이 공개한 합성 워크플로 4종이라 Laya 에 유리할 수 있다는 편향을 배제하지 못했습니다.

전망: 이 범주가 살아남는다면 승부는 「얼마나 맞히나」가 아니라 「틀릴 때를 아는가」에서 갈립니다. 확률이 말 그대로의 의미를 가질 때만 accept/escalate 같은 설계가 성립하고, 그때 비로소 값싼 판정기를 앞단에 두고 비싼 모델을 뒤로 미는 구조가 경제성을 만듭니다.

시장에서 관찰되는 이동

• 모델이 아니라 계약이 먼저 표준화됐습니다: Jev 의 /v1/systemone 요청 형식이 2주 만에 Ollama 의 기본 엔드포인트가 됐습니다. 범주 역사상 드문 속도이며, 모델을 교체 가능한 부품으로 만듭니다.
• 진입 장벽이 사실상 없음이 증명됐습니다: 68M 인코더(Anarkali)부터 학습 자체가 불필요한 방식(AnyJev·SemIf)까지 같은 계약을 만족시켰습니다. 독점 모델의 방어선은 제로샷 일반화와 캘리브레이션뿐입니다.
• 경쟁축이 품질에서 단가·지연·배치 위치로 내려갔습니다: Jev $0.042/1M(출력 무료) vs Cloudflare Clef $0.09/1M vs Laya 토큰당 $0. 가격이 이미 0 에 닿은 계층이 존재합니다.
• 독립 검증이 열기를 식히고 있습니다: 범주 공개 2.5주 만에 나온 첫 제3자 벤치마크가 「안정적 우위 없음」으로 결론냈고, 공개된 지표는 거의 전부 벤더 자체 평가입니다.
• 인접 시장은 실재합니다: LLM 관측·평가 플랫폼 시장은 2026년 26.9억 달러에서 2030년 92.6억 달러(CAGR 36.2%)로 전망되며, LLM-as-a-judge 는 인간 검수 대비 500~5,000배 저렴하되 인간 선호와 약 80% 일치 수준입니다. 판정 모델은 이 비용 곡선을 한 단계 더 내리려는 시도입니다.

활용 아이디어

시장에서 관찰되는 주요 활용 접근을 소개합니다.

1. 기존 분류기와 동일 조건 대조 — 이미 돌고 있는 분류 지점 한 곳을 골라, 현행 방식과 판정 모델을 같은 데이터·같은 측정 조건에서 비교하는 접근. Red Hat 결과가 보여준 대로 전용 소형 분류기가 이기는 경우가 드물지 않습니다.

2. 캘리브레이션을 먼저 재는 평가 — 정확도보다 ECE·Brier 를 먼저 측정하고, 홀드아웃으로 온도를 재조정한 뒤 임계값을 정하는 접근. 모델 카드 자신이 과신을 인정하고 재조정을 권고하는 사례가 있습니다.

3. accept/escalate 2단 구조 설계 — 값싼 판정기를 앞단에 두고 확신 구간만 자체 확정, 불확실 구간은 상위 모델이나 사람으로 올리는 접근. 공개 연구에서는 임계값에 따라 20~40%가 에스컬레이션됩니다.

주요 용어 설명

의사결정 모델 / System One 모델 — 글을 생성하는 대신 「선택지 중 하나」, 「점수」, 「예·아니오 확률」처럼 범위가 정해진 답을 돌려주는 모델입니다. 사람의 빠른 직관적 판단(시스템 1)에서 따온 이름이며, 소프트웨어가 그 값을 바로 조건문에 쓸 수 있다는 점이 핵심 주장입니다.
choice · noul · score — 이 범주의 질문 유형 3종입니다. choice 는 선택지 중 하나를 고르고(최대 255개), noul 은 조건이 참일 확률을 내고, score 는 순서가 있는 기준 위의 단계를 냅니다. Jev 가 붙인 이름이 그대로 업계 표준 어휘가 됐습니다.
캘리브레이션 / ECE — 모델이 「90% 확신」이라고 말할 때 실제로 열 번 중 아홉 번 맞는지를 보는 성질입니다. ECE(기대 캘리브레이션 오차)는 그 어긋남의 크기로, 낮을수록 확률을 믿을 수 있습니다. 임계값을 걸어 자동 처리하는 시스템에서는 정확도보다 중요할 수 있습니다.
비자동회귀(non-autoregressive) — 단어를 하나씩 이어 쓰지 않고 한 번의 연산으로 답을 내는 방식입니다. 생성을 하지 않으므로 훨씬 빠르지만, 대신 문장으로 설명하지 못합니다. Laya 가 33ms, 배치 7.2ms 를 내는 이유입니다.
인코더 모델 (BERT 계열) — 문장을 읽어 의미를 압축하는 데 특화된 구조로, 글을 쓰는 디코더(GPT 계열)와 대비됩니다. ModernBERT·DeBERTa 가 그 예이며, 작고 빠르지만 다루는 문맥 길이가 짧습니다.
RLCD — TypeSafe 가 Jev 에 적용했다고 밝힌 사후학습으로, 「사람이 선호하는 답변」이 아니라 「올바른 판정과 쓸 만한 확률」을 보상으로 삼습니다. 대화형 모델의 RLHF 와 목표가 다르다는 주장이며, 세부 방법은 공개되지 않았습니다.
LLM-as-a-judge — 큰 언어모델에게 다른 모델의 출력이나 사용자 입력을 평가하게 하는 방식입니다. 사람 검수보다 수백~수천 배 싸지만 인간 선호와의 일치는 약 80% 수준이고, 응답을 생성하므로 느립니다. 의사결정 모델이 대체를 노리는 바로 그 자리입니다.
가드레일 / 프롬프트 인젝션 — 가드레일은 AI 입출력을 정책에 맞게 걸러내는 장치이고, 프롬프트 인젝션은 악의적 입력으로 모델의 지시를 가로채는 공격입니다. Red Hat 벤치마크가 측정한 두 과제가 이 영역입니다.
accept/escalate — 확신이 높을 때는 스스로 확정하고 애매할 때만 상위 모델이나 사람에게 넘기는 2단 구조입니다. 값싼 판정기를 앞에 두어 전체 비용을 낮추는 설계이며, 확률이 정직할 때만 성립합니다.
