タスク指向対話システム（TOD）深層分析
技術構造・世界の主要システム・事業可能性

40年前の設計が、大規模言語モデルの時代に再び標準となった理由
レポート作成日：2026年9月30日 | 詳細版レポート | ID: TR-20260930-001

主要トレンド Top 5

1. 分解と再構成：大規模言語モデルが両端を担い、中央はコードが担う

現状：タスク指向対話（TOD）は従来、言語理解 → 対話状態管理 → 対話方策 → 応答生成という四つの部品に分けて設計されてきました。大規模言語モデル（LLM: Large Language Model）は、このうち両端にあたる言語理解と応答生成を事実上担うようになりました。しかし中央の二つ、すなわち対話状態管理（DST）と対話方策（Policy）は、今も決定的に動くコードとして残っています。近年の研究文献も、本番システムが「状態管理、個人化、検索、ツール・API 呼び出し、記憶のための外部モジュール」と組み合わされる構造を採ると記述しています（出典：LLM-Based Dialogue Agents）。

大規模言語モデルが置き換えた領域

• 意図分類：ルールや分類器 → プロンプトによる分類
• 応答生成：定型文 → 計算結果を説明する文章生成
• 領域転移：学習していない領域への対応力が大きく向上
• 多言語：言語ごとの構成を持たず単一モデルで処理

コードとして残る領域

• 対話状態管理：複数ターンにわたる項目と目標の確実な保持
• 対話方策：さらに尋ねるか、確認するか、答えるかの判断
• ツール呼び出し：外部 API やデータベース照会の検証可能な実行
• 安全規則：再現できなければならない安全・法令面の判断

展望：2026年の本番システムでは振り分け構成が一般的です。日常的なやり取りは安価なモデルで処理し、複雑なものだけ上位モデルへ引き上げます（出典：LLM Agents 2026）。これは費用と応答時間を同時に管理するための実務的な対応であり、方策判断がコード側にあってはじめて振り分けそのものが成立します。

📊 信頼性評価： 8.5/10
強み：学術文献と産業界の観察が一致しており、構造の記述が具体的
改善点：「振り分け構成が一般的」という採用率を示す定量調査は見当たらない

2. 顧客対応エージェントへの資金集中：Sierra 158億ドル、Decagon 45億ドル

現状：TOD の商業的な中心は顧客対応の自動化へ移り、資金の流入規模がこの分野の定義そのものを変えつつあります。Sierra は2026年5月、GV と Tiger Global が主導する9億5,000万ドルのシリーズ E により企業価値158億ドルを記録し、累計調達額は15億8,500万ドルに達しました。売上は2024年末の2,600万ドルから2025年末には約1億3,000万ドル、2026年5月には年換算2億ドルへと伸びています（出典：Sacra — Sierra）。

主要企業の評価額

• Sierra：158億ドル（2026年5月）、年換算売上2億ドル
• Decagon：45億ドル（2026年1月）、年換算売上およそ3,500万ドル
• Parloa：企業価値30億ドル、累計調達5億6,000万ドル超
• Cognigy：NICE がおよそ9億5,500万ドルで買収（2025年）

注目すべき倍率

• Decagon：売上に対する評価倍率がおよそ128倍
• Cognigy 買収：専門家は25倍の上乗せと評価
• 累計調達額首位：Sierra のおよそ16億ドル
• 解釈：現在の売上ではなく置き換えの対象市場への賭け

展望：この倍率は、顧客対応の人件費そのものを置き換え対象と見なす立場でのみ説明がつきます。投資家が狙っているのはソフトウェア市場ではなく人件費市場の一部です。裏を返せば、実測した成果が想定に届かない場合、調整の幅も同じだけ大きくなります。

📊 信頼性評価： 9.0/10
強み：金額・時期・主導投資家が明示された一次追跡データに基づく
改善点：年換算売上は非上場企業の推定値であり、誤差が含まれる可能性がある

3. 構築基盤市場の四層化：大手クラウド・専門企業・オープンソース

現状：自社構築型の基盤市場は既存環境への依存度を軸にはっきりと分かれました。Google Dialogflow CX は視覚的な状態遷移図を備え、分岐の多いコンタクトセンター向けの流れを確認・修正しやすい点が強みです。Amazon Lex は AWS の Lambda や Connect と連携済みの音声業務に適します。Microsoft Copilot Studio は Microsoft 365、Teams、Dynamics 365 を中心とする環境に最適化されています（出典：Rasa 比較記事）。

選定を分ける基準

• データ主権：金融・防衛の外部遮断要件 → Rasa の自社運用
• 既存環境：AWS なら Lex、Microsoft 365 なら Copilot Studio
• 流れの複雑さ：分岐の多い自動音声応答 → Dialogflow CX
• 適用範囲：全社規模の複数エージェント → Kore.ai

料金体系（2026年1月時点）

• Dialogflow CX：要求ごとの生成課金に加え、1,000イベントあたりのセッション保存課金
• Kore.ai：個別見積もり。一般的な導入規模は年間30万ドル以上
• Rasa：オープンソース基盤のため、費用は設備と人員へ移る
• 示唆：従量課金が対話設計そのものを直接制約する

展望：要求ごとの課金は「やり取りの回数を減らす設計」に経済的な動機を与えます。不要な聞き返しが一度増えるだけで費用となり、同時に離脱の要因にもなります。つまり対話状態管理の品質が、そのまま単価だということです。

📊 信頼性評価： 7.5/10
強み：料金体系と時点が明示されており、調達判断にそのまま使える
改善点：主要な出典が競合企業（Rasa）の記事であり、偏りの可能性がある。各社の公式資料との照合を推奨
🔗 関連リンク： Google Dialogflow CX | Amazon Lex | Copilot Studio | Rasa | Kore.ai

4. 導入率と実測成果の隔たり：導入66%、明確な成果は23%

現状：導入は速い一方で、検証された成果は遅れています。Salesforce の調査では、AI エージェントを運用する顧客対応部門は2025年の39%から66%へ増加し、Gartner は顧客体験部門の責任者の91%が経営層から導入の圧力を受けていると報告しています。しかし、AI エージェントから明確な投資対効果を得たと回答した組織はおよそ23%にとどまります（出典：AI Agent Statistics 2026）。

自動解決率の実際

• 提供企業の主張：Decagon は80%
• 基盤側の中央値：Zendesk の大企業向けで41.2%
• 中立的な観測：導入1年目45〜60%、成熟段階で65〜75%
• 示唆：提供企業の数値と現場の中央値の差はおよそ2倍

時間経過による投資対効果

• 1年目：平均41%
• 2年目：87%
• 3年目：124%超
• 回収期間：中央値5.4か月（Forrester の経済効果分析）
• 業種別導入率：通信95%・銀行92%・医療79%

展望：この推移が示すことは明確です。TOD は1年目で採算に乗る事業ではありません。1年目の41%は導入費用と運用の習熟に費やされ、実質的な利益は2〜3年目に現れます。短期的な成果を前提にした導入判断は、2年以内の撤退につながる危険が高いといえます。

📊 信頼性評価： 8.0/10
強み：複数の出典（Salesforce・Gartner・Forrester・Zendesk）が相互に裏づけられ、楽観・悲観の双方の数値を併記
改善点：集約記事を経由した二次引用が含まれるため、元の調査報告の直接確認が必要
🔗 関連リンク： Customer Service Automation Statistics | AI Agent Adoption 2026 | Zendesk

5. 評価手法の空白：指標は正確さを測り、現場は到達を問う

現状：TOD 研究の標準的な評価データにはMultiWOZ と Schema-Guided Dialogue（SGD）があります。SGD は16領域26サービスにわたる16,000件超の対話で構成され、試験用データに学習していない領域を含めることで汎化能力を測ります。MultiWOZ は人間同士の対話を収集したもので、2.4版では検証用・試験用データを付け直して評価の精度を高めました（出典：Awesome DST）。

評価データが測るもの

• Joint Goal Accuracy：状態の全項目が正解と一致した割合
• 項目別 F1：個々の項目の抽出精度
• 領域汎化：学習していないサービスへの対応力
• 性質：モデルの能力の測定

現場が必要とするもの

• 課題達成率：所定のやり取りの中で目的を果たせたか
• 対話の費用：何回のやり取りを要し、何回聞き返したか
• 引き継ぎ率：人へ回った割合とその理由
• 性質：サービスの成果の測定

展望：この空白は実務で繰り返し観察されます。状態管理の精度が高くても対話が目的地に届かない事例は存在し、安全性や正確さを中心とした出荷判定はこれを検出できません。課題達成と対話費用という二つの軸を運用指標に組み込むことが、今後1〜2年の実質的な課題です。

📊 信頼性評価： 7.0/10
強み：データ規模と構成が一次文献で確認でき、評価軸の区別が明確
改善点：検索で得た文献が2020〜2023年に集中し、2026年の最新動向を反映していない。本節の「空白」という主張は筆者の分析である旨を明記
🔗 関連リンク： MultiWOZ | Schema-Guided Dialogue | Towards LLM-driven DST

競争環境と市場での位置づけ

四層の市場構造

TOD 市場は買い手が何を購入しているかを基準に四つの層へ分かれます。最上位層はソフトウェアではなく成果を販売しており、これが評価額の差を説明する根拠となっています。

層代表企業販売対象課金方式主な顧客
第1層 統合型エージェントSierra, Decagon, Parloa解決済みの問い合わせ（成果）解決件数ごと大規模な顧客対応部門
第2層 大手クラウドDialogflow CX, Amazon Lex, Copilot Studio構築道具と周辺環境要求・セッション単位既存クラウド利用企業
第3層 大企業向け専門Kore.ai, Cognigy（NICE）, Yellow.ai全社規模の基盤年間契約（30万ドル〜）大企業の顧客体験・業務自動化
第4層 オープンソースRasa完全な統制権利用許諾と自社運用金融・防衛・規制産業

市場の動き 5点

  • 成果連動の課金へ：第1層は席数ではなく解決件数で課金し、ソフトウェア予算ではなく人件費予算を狙っています。
  • 基盤側の垂直統合：NICE による Cognigy 買収（約9億5,500万ドル）は、コンタクトセンター事業者が対話エンジンを内製化する流れを示します。
  • 音声の再浮上：音声に特化した Parloa が1年足らずで評価額を3倍（30億ドル）にした事例は、次の成長軸が文字のその先にあることを示唆します。
  • データ主権に値段がつく：外部遮断や自社設置の要件が Rasa 系の存立根拠であり、規制産業ではクラウドの利便性より優先されます。
  • 期待と成果の差の拡大：導入66%に対し明確な成果23%という隔たりは、今後2年の提供企業の選別と再編を促します。

活用アイデア

市場で観察される主要な活用の進め方をご紹介します。

1. 単一領域での試行 - 問い合わせの上位3種類に絞って適用し、自動解決率を実測してから範囲を広げます。

2. 状態管理のコード分離 - 項目と目標の状態をプロンプトではなく決定的なコードに保持し、再現性と調査のしやすさを確保します。

3. 課題達成の指標化 - 正確さ中心の評価に、所定回数内の目的達成率と聞き返し率を加えて運用指標とします。

要旨

重要なポイント

  • 構造は戻ってきた：大規模言語モデルが言語理解と応答生成を担う一方、対話状態管理と方策はコードとして残りました。40年前の四部品設計が今も骨格です。
  • 資金は成果を買っている：Sierra 158億ドル、Decagon 45億ドルという倍率は、ソフトウェアではなく人件費市場への賭けです。
  • 隔たりが最大の危険：導入66%に対し明確な成果23%。提供企業の主張する自動解決率80%と基盤側の中央値41.2%の差が実態です。
  • 利益は2〜3年目：投資対効果は1年目41%、2年目87%、3年目124%と推移します。短期回収を前提とした導入は失敗しやすいといえます。
  • 評価に空白がある：評価データは状態管理の精度を測りますが、現場は「対話が目的地に届いたか」を測る必要があります。

選定の指針

大規模な顧客対応部門で早期の成果が必要 → 第1層の統合型（Sierra・Decagon）
理由：構築の負担なく解決件数課金で始められます。ただし依存と単価上昇の条件は契約に明記すべきです
特定クラウドへの投資が済んでいる → 第2層の大手クラウド
理由：AWS なら Lex、Microsoft 365 なら Copilot Studio。連携費用が最も小さくなります
全社規模で複数のエージェントを展開 → 第3層の専門基盤（Kore.ai）
理由：年間30万ドル以上の規模では、統一した管理体制の利点が生じます
金融・防衛・医療などデータ主権が必須 → 第4層のオープンソース（Rasa）
理由：外部遮断環境で運用できる事実上唯一の選択肢です。ただし費用は人員へ移ります

総合評価：条件付きで前向き — 技術の成熟度と資金流入は堅調ですが、実測した成果が期待に届かない期間が2〜3年続く見通しです。事業機会は汎用の対話サービスではなく、領域を絞り、検証できる成果指標を備えた取り組みにあります。

主要用語の説明

タスク指向対話（TOD） - 予約や問い合わせ、相談のように目的が定まった会話を扱うしくみ。雑談と違い、「用事が済んだか」で成否を判定します。
対話状態管理（DST） - 複数のやり取りにわたって確定した情報（行き先、日付、人数など）を覚えて更新する部品。人でいえば「聞いた内容を書き留めておく手控え」にあたります。
対話方策（Policy） - 次に何をするかを決める部品。さらに尋ねるか、確認するか、答えを出すかを判断します。
自動解決率 - 人の担当者に引き継がずに AI が完了させた問い合わせの割合。提供企業の宣伝で最も多く引用されますが、定義が各社で異なるため比較の際は注意が必要です。
Joint Goal Accuracy - 対話状態管理の評価指標。一つのやり取りですべての項目が正解と一致してはじめて得点となるため、一つ違うだけで零点という厳しい尺度です。
成果連動課金 - 席数や呼び出し回数ではなく解決した件数に課金する方式。提供側が品質の責任を分かち合う構造になります。
MultiWOZ / SGD - TOD 研究の標準的な評価データ。SGD は16領域26サービス、16,000件超の対話からなり、試験用データに学習していない領域を含みます。
