상태 추적은 프로그래밍이 되고, 정책은 강화학습으로 돌아왔다
보고서 작성일: 2026년 9월 30일 | 표준 보고서 | ID: TR-20260930-002

주요 트렌드 Top 5

1. 상태 추적이 프로그래밍 문제가 되다 — 함수 호출이 표준 인터페이스로

현황: 대화 상태 추적(DST)은 오랫동안 슬롯 채우기 분류 문제로 다뤄졌습니다. 2024년 이후 이 정의가 바뀌었습니다. DST를 함수 호출(function calling)로 표현하자 7B·13B급 모델이 ChatGPT가 세운 기존 최고 성능을 앞질렀고, ChatGPT 자체도 평균 Joint Goal Accuracy가 5.6%p 개선됐습니다 (출처: arXiv 2402.10466). RefPyDST는 한 걸음 더 나가 DST를 파이썬 프로그래밍 과제로 정식화하고, 언어의 상호참조(coreference)를 변수 참조로 명시적으로 모델링했습니다.

무엇이 달라졌나

• 표현 방식: 슬롯 분류 → 타입이 있는 함수 시그니처
• 상호참조: 「그거로 해줘」를 변수 참조로 처리
• 스키마 주입: 도메인 정의를 프롬프트에 직접 제공
• 검증: 구조화 출력이라 파싱 단계에서 형식 검사 가능

데이터 비용이 무너졌다

• 문맥 내 학습(ICL): 파라미터 갱신 0회, 데이터 극소량
• few-shot 우위: 소량 설정에서 학습한 모델을 능가
• 검색 증강 ICL: 다양한 예시를 골라 성능 개선
• 의도 기반 ICL: 예시 선택을 의도 단위로 구조화

전망: 라벨링된 목적형 대화를 수집·주석하는 비용이 이 분야의 오랜 병목이었습니다. 함수 호출 인터페이스와 문맥 내 학습은 그 병목을 우회합니다. 다만 해석 가능성이 새 과제로 떠올라, 상태를 자연어 요약으로 표현해 견고성과 설명력을 동시에 확보하려는 연구가 진행 중입니다.

강점: 구체적 수치(+5.6%p JGA)와 1차 논문 출처 명시
개선점: 7B/13B 모델이 앞선 것은 특정 벤치마크 조건이며 전면적 우위는 아님

2. 대화 정책이 강화학습으로 돌아왔다 — 턴 단위에서 궤적 단위로

현황: 대화 정책(Dialogue Policy)은 전통적으로 마르코프 결정 과정(MDP)으로 정식화되어 강화학습으로 최적화돼 왔습니다. LLM 시대에 한동안 프롬프트로 대체되는 듯했으나, 다시 강화학습이 중심으로 복귀하고 있습니다. 최근 조사 논문은 RL이 두 가지 방식으로 작동한다고 정리합니다 — 구조화된 계획 과정의 외부 안내자이거나, LLM 내재 계획 정책을 직접 진화시키는 내부 동력입니다 (출처: The Landscape of Agentic RL for LLMs).

핵심 전환 — 궤적 단위 보상

• 문제: 장기·희소 보상 환경에서 턴 단위 최적화가 실패
• HiPER: 상위 계획자와 하위 구성요소로 분해
• 효과: 즉시 보상에서 누적 궤적 수익으로 전환
• 의미: 초기 행동의 결과가 시간을 타고 전파됨을 반영

제어 가능성을 얹는 접근

• ChatSOP: 표준운영절차(SOP) 유도 MCTS 계획
• Interactive Planner-R1: 자율 환경 탐색 기반 궤적 RL
• DialogXpert: LLM 사전지식 + 온라인 가치 기반 RL
• PPDPP: 정책 계획자를 탈착 가능한 모듈로

전망: 이 흐름의 함의는 분명합니다. 프롬프트만으로는 다중 턴 의사결정이 풀리지 않는다는 것이 연구 공동체의 잠정 결론입니다. 특히 「탈착 가능한 정책 계획자」 형태는 거대 모델을 재학습하지 않고 정책만 교체할 수 있어 실무 적용 가능성이 높습니다.

📊 신뢰도 평가:8.0/10
강점: 조사 논문과 개별 기법 논문을 교차 인용해 흐름의 존재를 뒷받침
개선점: 각 기법의 정량 성능 비교는 벤치마크가 달라 직접 대조하지 않음

3. 작은 모델의 역습 — 특화 미세조정이 규모를 이기는 조건

현황: 목적형 대화는 과제 범위가 좁다는 특성이 있어 소형 언어모델(SLM)에 유리합니다. 최근 분석은 0.5~3B 규모 모델이 주어진 과제 전반에서 우수한 효율 지표를 기록하며, 이는 한계 정확도보다 추론 효율을 우선하는 운영 환경에 소형 모델을 배치할 정량적 근거가 된다고 결론짓습니다 (출처: Task-Specific Efficiency Analysis).

압축 기법의 조합 효과

• 3단 파이프라인: 가지치기 → 증류 → 양자화
• 결과: 같은 크기를 처음부터 학습한 모델보다 우수
• Phi-4-mini: AlpacaEval 80.5
• Mistral-7B: 77.0 — 파라미터는 약 2배

목적형 대화에서의 근거

• 도구 호출: 표적 미세조정한 SLM이 대형 모델을 능가
• Spec-TOD: TOD 특화 지시 튜닝 프레임워크
• 다중 의도 분류: 7B급 공개 모델 벤치마킹(MultiWOZ 2.1)
• 전제: 도메인이 좁고 스키마가 고정될수록 유리

전망: 이는 비용 구조를 바꿉니다. 요청당 과금이 대화 설계를 제약하는 상황에서, 특화 소형 모델로 일상적 턴을 처리하고 복잡한 턴만 대형 모델로 올리는 계층적 배치가 표준이 될 가능성이 높습니다. 다만 이 전략은 턴의 난이도를 판정하는 라우터가 필요하며, 그 판정 자체가 정확해야 합니다.

📊 신뢰도 평가:7.5/10
강점: Phi-4-mini 80.5 vs Mistral-7B 77.0 등 직접 비교 가능한 수치 제시
개선점: AlpacaEval은 범용 지시 수행 지표로 TOD 성능의 직접 대리 지표가 아님
🔗 관련 링크: Task-Specific Efficiency Analysis | SLM for Agentic Tool Calling | Spec-TOD | Model Compression Survey

4. 평가가 턴에서 궤적으로 — τ-bench와 사용자 시뮬레이터

현황: 평가 패러다임이 바뀌고 있습니다. τ-bench는 소매·항공 도메인에서 고객 응대 에이전트를 평가하며, 이전 도구 사용 벤치마크에 없던 세 가지를 도입했습니다 — ① 다중 턴 대화를 이끄는 사용자 시뮬레이터 ② 에이전트가 반드시 지켜야 하는 도메인별 정책 ③ 행동이 데이터베이스에 지속적 영향을 남기는 상태 지속 시나리오입니다 (출처: Tau-Bench 2026).

무엇이 문제였나

• 기존 지표: Joint Goal Accuracy 등 턴 단위 라벨 정확도
• 한계: 정확도가 높아도 대화가 목표에 수렴했는지 알 수 없다
• τ-bench: 궤적(trajectory) 지표를 명시적으로 겨냥
• τ²-bench: 양방 제어(dual-control) 환경으로 확장

사용자 시뮬레이터라는 새 변수

• EYT-Bench: 페르소나 기반 시뮬레이터 + 대상 모델 + 독립 심판단 3자 분리
• 측정 대상: 페르소나 일관성·의도 변화 추적·감정 동역학·목표 달성
• SimulatorArena: 시뮬레이터가 믿을 만한 대리인인가를 검증
• 경고: 협조적 시뮬레이터만으로는 견고성 평가 불가

전망: 이 전환은 실무에 직접적입니다. 「LLM은 변화하는 사용자 의도에서 길을 잃는다」는 제목의 연구가 나올 만큼, 다중 턴에서의 의도 추적은 여전히 취약합니다. 안전성·정확도만 재는 기존 출하 판정으로는 대화가 막혀 있어도 통과시킵니다. 궤적 지표의 운영 편입이 향후 1~2년의 과제입니다.

📊 신뢰도 평가:8.5/10
강점: τ-bench 구성요소가 1차 출처로 확인되며, 후속 벤치마크(τ²·EYT)까지 계보가 연결됨
개선점: 모델별 τ-bench 점수를 제시하지 않아 난이도 체감은 전달되지 않음
🔗 관련 링크: Tau-Bench 2026 | EYT-Bench | SimulatorArena | LLMs Get Lost in Evolving User Intent

5. 모듈형의 재평가 — 종단간이 목적형 대화를 이기지 못한 이유

현황: 종단간(end-to-end) 신경망이 모듈형 파이프라인을 대체하리라는 예측은 목적형 대화에서는 완전히 실현되지 않았습니다. 문헌은 그 이유를 분명히 합니다 — 모듈형 시스템은 특정 과제 제약을 지키도록 프로그래밍하기가 더 쉽습니다. 흥미롭게도 목적형 과제의 종단간 모델조차 검색 메커니즘·지식베이스·도메인 온톨로지 형태의 암묵적 모듈을 덧붙여 작동합니다 (출처: End-to-End Spoken Dialogue Systems).

모듈형이 남은 이유

• 제약 준수: 규정·정책을 코드로 강제할 수 있다
• 검증 가능성: 각 단계의 중간 표현을 감사할 수 있다
• 부분 교체: 한 부품만 개선·롤백 가능
• 재현성: 같은 입력에 같은 판단을 보장하기 쉽다

종단간이 앞서는 영역

• 음성 대화: 오디오 이해–생성을 하나의 신경망으로
• 자연스러움: 중간 표현 손실이 없어 운율·반응성 우수
• 전이중(full-duplex): 끼어들기·동시 발화 처리
• Kimi-Audio: 입력과 출력 측을 분리해 재학습 없이 개선

전망: 현재 형성 중인 합의는 계층적 절충입니다. 음성 입출력은 종단간으로, 상태와 정책은 모듈로 두는 구성입니다. 전이중 음성 대화 조사 논문이 「결정 상태 기계(decision state machine)」를 구조 계층의 핵심으로 제시하는 것은 이 절충을 잘 보여줍니다 — 가장 신경망적인 영역에서도 상태 기계는 남습니다.

📊 신뢰도 평가:7.0/10
강점: 모듈형 존속 근거를 1차 문헌에서 확인하고 음성 영역의 예외를 함께 제시
개선점: 「합의가 형성 중」이라는 판단은 본 보고서의 분석이며 정량 근거는 없음
🔗 관련 링크: Full-Duplex Spoken Dialogue Survey | X-Talk: Potential of Modular | Incremental Dialogue in the Age of LMs

기술 접근법의 지형

4계층 기술 구조

연구·구현 접근법은 무엇으로 행동을 결정하는가를 기준으로 네 계층으로 나뉩니다. 아래로 갈수록 제어 가능성이 커지고 데이터·연산 요구가 늘어납니다.

계층대표 기법학습 요구강점약점
T1. 프롬프트·ICL함수 호출 DST, RefPyDST, 검색증강 ICL파라미터 갱신 0즉시 적용·도메인 이전 용이비결정성·해석 어려움
T2. 특화 미세조정Spec-TOD, SLM 도구호출, 증류·양자화중간 (지시 튜닝)추론 비용 최소·안정성도메인 고정·재학습 부담
T3. RL 정책 최적화HiPER, Planner-R1, ChatSOP, PPDPP높음 (환경·보상 설계)장기 과제·궤적 최적화보상 설계 난이도·시뮬레이터 의존
T4. 종단간 음성전이중 대화, Kimi-Audio매우 높음자연스러움·저지연제약 준수·감사 곤란

기술 동향 5가지

  • 인터페이스의 표준화: 함수 호출이 DST의 사실상 표준 표현이 되며, 타입 검사와 구조화 출력이 신뢰성의 1차 방어선이 되고 있습니다.
  • 최적화 단위의 상승: 턴 단위 정확도에서 궤적 단위 수익으로 이동하며, 이는 평가와 학습 양쪽에서 동시에 일어납니다.
  • 규모의 재협상: 좁은 과제에서는 0.5~3B 모델이 효율 우위를 보이며, 계층적 모델 배치가 비용 구조를 재편합니다.
  • 시뮬레이터의 부상: 사용자 시뮬레이터가 학습 환경이자 평가 도구가 되면서, 시뮬레이터 자체의 신뢰성이 새 연구 주제가 되었습니다.
  • 모듈의 존속: 가장 신경망적인 음성 영역에서도 결정 상태 기계가 남아, 상태와 정책의 모듈화는 사라지지 않았습니다.

접근법별 특성 비교

평가 벤치마크 세대별 구성요소

주: 각 벤치마크가 갖춘 구성요소 수(다중 턴 · 사용자 시뮬레이터 · 정책 준수 · 상태 지속 · 도구 호출)를 셈한 것입니다. 출처 기술에 근거하되 집계는 본 보고서가 수행했습니다.

📊 신뢰도 평가:7.0/10
강점: 계층 구분이 「학습 요구량」이라는 관찰 가능한 기준에 근거
개선점: 4계층 분류와 레이더 점수는 본 보고서의 평가이며 표준 분류가 아님

활용 아이디어

연구 동향에서 관찰되는 주요 적용 접근을 소개합니다.

1. 상태 추적의 함수 호출 전환 - 슬롯 추출을 타입이 있는 함수 시그니처로 바꿔 파싱 단계에서 형식을 검증합니다.

2. 계층적 모델 배치 - 일상 턴은 특화 소형 모델로, 복잡한 턴만 대형 모델로 올려 추론 비용을 낮춥니다.

3. 궤적 지표 도입 - 턴 단위 정확도 옆에 N턴 내 목표 달성률과 재질문률을 나란히 둡니다.

종합 요약

핵심 요점

  • DST의 재정의: 슬롯 분류에서 함수 호출·프로그래밍으로 바뀌며, 7B급 모델이 기존 최고 성능을 넘어섰습니다(ChatGPT 대비 +5.6%p JGA).
  • 정책의 복귀: 프롬프트만으로 다중 턴 의사결정이 풀리지 않는다는 인식 아래, 궤적 단위 강화학습이 다시 중심에 섰습니다.
  • 규모의 역전: 좁은 과제에서 0.5~3B 모델이 효율 우위를 보이며, Phi-4-mini가 절반 파라미터로 Mistral-7B를 앞섭니다(80.5 vs 77.0).
  • 평가의 이동: τ-bench가 사용자 시뮬레이터·정책 준수·상태 지속을 도입해 턴 정확도로는 목표 수렴을 알 수 없다는 한계를 정면으로 다룹니다.
  • 모듈의 존속: 종단간은 음성에서 앞서지만, 제약 준수가 필요한 목적형 대화에서는 상태·정책의 모듈화가 유지됩니다.

선택 가이드

도메인이 자주 바뀌고 빠른 시작이 필요 → T1 프롬프트·ICL
이유: 파라미터 갱신 없이 스키마만 바꾸면 됩니다. 단 비결정성을 상태로 굳히는 설계가 필수
트래픽이 많고 단가가 중요 → T2 특화 미세조정
이유: 추론 비용이 지배적일 때 소형 특화 모델의 효율 우위가 가장 큽니다
다중 턴 목표 달성률이 핵심 지표 → T3 RL 정책 최적화
이유: 궤적 단위 보상만이 장기·희소 보상 문제를 다룹니다. 단 시뮬레이터 신뢰성 검증 선행
음성 응답성·자연스러움이 제품 가치 → T4 종단간
이유: 전이중 상호작용은 종단간이 유리합니다. 단 정책 준수는 별도 모듈로 확보

종합 평가: 긍정적 — 기술 성숙이 빠르고 방향이 수렴하고 있습니다. 다만 수렴 지점은 「LLM이 전부를 대체한다」가 아니라 「LLM이 이해와 생성을, 코드와 강화학습이 기억과 판단을 맡는다」는 분업 구조입니다.

종합 평가: 주장의 대부분이 arXiv 1차 문헌과 벤치마크 공식 설명에 근거하며, 수치 인용 시 출처와 조건을 함께 밝혔습니다.

주요 강점: 함수 호출 DST(+5.6%p)·Phi-4-mini(80.5 vs 77.0) 등 검증 가능한 수치, 연구 계보의 연결(τ-bench → τ²-bench → EYT-Bench)

개선 우선순위: ① 모델별 τ-bench 점수 보강 ② AlpacaEval을 TOD 대리 지표로 쓴 한계 보완 ③ RL 기법 간 정량 비교 추가

주요 용어 설명

Joint Goal Accuracy (JGA) - 대화 상태 추적의 대표 지표. 한 턴에서 모든 슬롯 값이 정답과 일치해야 점수를 얻으므로, 하나만 틀려도 0점인 엄격한 척도입니다.
문맥 내 학습 (In-Context Learning, ICL) - 모델의 가중치를 바꾸지 않고 프롬프트에 예시를 넣어 과제를 가르치는 방법. 데이터 수집 비용을 크게 낮춥니다.
함수 호출 (Function Calling) - 모델의 출력을 자유 문장이 아니라 정해진 함수와 인자 형태로 받는 방식. 형식 검증이 가능해 신뢰성이 올라갑니다.
궤적 단위 보상 (Trajectory-level Reward) - 매 턴의 즉시 점수가 아니라 대화 전체의 결과로 학습하는 방식. 초기 선택의 장기 영향을 반영합니다.
지식 증류 (Knowledge Distillation) - 큰 모델의 판단을 작은 모델에 옮겨 심는 기법. 가지치기·양자화와 함께 쓰면 같은 크기를 처음부터 학습한 모델보다 좋아집니다.
사용자 시뮬레이터 (User Simulator) - 사람 대신 대화를 이끄는 프로그램. 학습 환경이자 평가 도구로 쓰이며, 시뮬레이터가 실제 사용자를 대표하는가가 최근 쟁점입니다.
전이중 대화 (Full-Duplex Dialogue) - 양쪽이 동시에 말할 수 있는 대화. 끼어들기와 맞장구를 처리해야 하며 음성 시스템의 난제입니다.
